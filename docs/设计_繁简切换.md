# 设计: 简体 / 繁体切换

设定里选「简体 / 繁体」，繁体模式下对白、人名、物品、技能、界面文字都是繁体。做法和简体一致：**导入时一次性生成，运行时不做简繁转换**。

## 1. 为什么这样设计

- 原版文本是 Big5 繁体。内容包由资源生成工具 从玩家自己的原版生成, 生成时一次性转成简体 (OpenCC t2s + 字库字形修正), 这是**唯一的转换点**。内容包 `game/content/tdj/` 里存的是简体，运行时没有任何转换。
- 内容包已有叠加机制（`docs/内容格式.md` §4）：数据表按键深合并，普通文件整文件替换。但 `stage.json`（关卡名、简报）这类**混合文件**不能整文件替换（里面还有地图事件等），需要字段级叠加。
- 图片里的字不用处理：标题「神魔至尊傳」、标题卡「第零幕 獨行」本来就是繁体书法图，简体模式下也这样显示。

## 2. 语言设定与生效时机

- 设定项 `lang`：`hans`（简体，缺省）/ `hant`（繁体）。设定面板（F1）第一组，说明写「对白马上生效，屏幕上已经画好的菜单文字下个画面再换」。
- 切换时 `Content.set_lang(lang)` 重建数据表缓存、`UiStrings.reload()`；已经建好的界面对象 (菜单文字等) 保持旧文字，下个画面起是新语言；**对白例外，马上生效** (2026-10-25 起): `ContentDB.text_groups(路径)` 对同一路径永远返回同一个数组，切语言 / 重载内容包时 `_refresh_live_groups` **原地**换成新语言的内容，关卡 / 城镇对象 (`BattleStage.emsg` / `RpgStage.emsg`) 手里的引用自动跟上，所以之后的每一句对白立即是新语言，已经显示在屏幕上的那一句不动 (`game/tests/test_lang_live.gd`)。单位名、物品名、技能名本来就是每次从数据表现取，同样即时。
- 命令行 `--lang=hans|hant` 临时覆盖（截图/测试用，不写设定文件）。

## 3. 数据: 语言叠加层 (locale overlay)

导入工具同时生成繁体，但**只存与简体不同的文字**，放在内容包的 `locale/hant/` 下，路径与包内文件一一对应：

```
game/content/tdj/locale/hant/
  data/items.json  skills.json  units.json  enums.json     # 表: 只含 {键, 文字字段}
  stages/NN/text.json   towns/NN/text.json                 # 对白: groups 整个替换
  stages/NN/stage.json                                     # 只含 {name, briefing:{title,win,lose}}
  text/system.json                                         # 按表名替换
game/content/remake/locale/hant/text/ui.json               # 界面文案: 按键合并
```

**叠加规则**（`ContentDB`，`lang != "hans"`）：读一个 JSON 时，先得到原有结果（包叠加后），再对每个包按加载顺序合上 `locale/<lang>/<同路径>`：对象递归合并，数组与标量整个替换（`deep_merge`）。数据表先按原规则建好，再把 locale 里的记录按键深合并进去。`text/system.json`、`ui.json` 沿用各自的「按表名 / 按键」合并。简体模式完全不读 `locale/`。

**生成**：资源生成工具对每个输出文件**分别按简体和繁体各出一遍，逐字段比对，只把不同的叶子写进 `locale/hant/`**（结构自动与简体一致，不会漂移）。`locale/` 与内容包一样是生成物，不手改。

## 4. 手写文字 (不是原版文本, 没有繁体原文)

- **ui.json 与 enums.json**（界面文案、数据表编号字段的显示名）：简体手写，繁体用 OpenCC `s2twp` 转后按人工校对表逐条修正，产物进库 (改了简体文案要同步改 `locale/hant/text/ui.json`)。ui.json 里有的原版文字（标题菜单、营地菜单等）优先取原版繁体原文。
- **代码里写死的玩家可见文字**：一律走 `UiStrings.t(键, 参数)`，简体写进 `ui.json`，繁体由上一步生成。状态名（攻击提升等）也走文案表：简体写简体，繁体沿用原版繁体原文。
- `tools/checks/check_ui_text.py`（进 `ci fast`）扫描 `.gd` 里的中文字符串字面量，不在白名单（调试输出、开发者报错、注释）里的就报错，防止以后又写死文字。白名单 `tools/checks/ui_text_allow.txt` 入库。

## 5. 字体

- 默认思源黑体是完整字库，繁体字齐全（只缺 `‧`，由 `UiText.SUBST` 换成 `·`）。
- 霞鹜文楷、思源宋体是裁过的子集（取字范围含 `locale/hant` 与繁体 ui.json 用到的字，约 2626 个繁体字），子集重裁需要上游字体文件。缺字时回退到自带思源黑体兜底，不依赖各机器的系统字体；否则回退字形更粗，会出现「个别字特别粗」。`check_font.py` 对繁体文本同样检查缺字。
- 个别简繁字形不同的字（如「闇」「着/著」）沿用现有字形取舍，不另处理。

## 6. 不做

- 运行时简繁转换（没有 OpenCC 词表，不做一对多猜测）。
- 繁体 AI 放大图/视频的重新生成（图片里的字本来就是繁体书法）。
- 视频里的字幕：25 段 Bink 过场没核对有无内嵌字幕。
- 其他语言（结构上 `locale/<lang>/` 可以扩展，目前只有 hant）。

## 7. 测试与验证

- `ContentDB`：locale 叠加合并规则（对象深合并、数组替换、表按键合并、简体模式不读 locale、切换后缓存重建），见 `game/tests/test_locale.gd`。
- 回归基线默认简体。
