# 新游戏 / 魔改接入指南

面向**内容作者**: 想在这个引擎上做一个改动包 (v2 魔改, 在原版内容上改) 或一个全新游戏 (v3, `base: []`), 只加数据、不改引擎代码。
给引擎开发者的贡献流程见根目录 `CONTRIBUTING.md`; 内容包每个字段的权威说明见 [内容格式.md](内容格式.md)。

本指南里每条命令都在仓库根目录执行, 并实际跑通过 (见各章「预期」)。附录: [指令表](剧情脚本格式_指令表.md) (生成) · [保留变量表](保留变量表.md) (生成) · [规则参数表](规则参数表.md) (生成)。

## 第 0 章 先决条件与目录约定

- 引擎: Godot 4.7.2 (`tools/godot/godot`, 下载见 `tools/ci_install_godot.sh`), Python 3.10+ (校验工具纯 Python, 不需要 Godot 和原版资源)。
- 自检环境: `python3 tools/paths.py` (列出原图仓库 / Godot / Python 是否就位; 没有原版资源也能做改动包的数据与校验, 只是无法跑画面)。
- 内容包 = 一个目录, 放在 `game/content/<包名>/` (随引擎发布) 或玩家目录 `user://content/<包名>/` (Linux: `~/.local/share/godot/app_userdata/<应用名>/content/`); `game/content/templates/<包名>/` 是引擎自带的模板, 也能直接 `--content=` 选用。同名时 `res://content` 优先于 templates, 再优先于 `user://content`。
- 先决定你做哪一种:

| | 改动包 (v2 魔改) | 全新游戏 (v3) |
|---|---|---|
| `base` | `["tdj"]` (改原版数据) 或 `["remake"]` (还要用复刻版界面) | `[]` |
| 数据表 | 只写要改的记录, 按键深合并 | 9 张表都要自带 |
| 界面/字体 | 沿用 remake | 自带 `ui_theme/{layout,fonts,assets}.json` |
| 起点 | 沿用原版第 0 关 | 用 `manifest.start` 指定 |
| 起手模板 | `game/content/example_mod/` | `game/content/templates/minimal_game/` |

- 版权: **不要分发原版素材** (图/音/视频/对白原文)。改动包只带你自己的改动; 原版内容由玩家自己的游戏生成 (资源生成工具)。

## 第 1 章 五分钟: 复制示例包并启动

```bash
cp -r game/content/example_mod game/content/my_mod
sed -i 's/"id": "example_mod"/"id": "my_mod"/' game/content/my_mod/manifest.json     # id 必须等于目录名
python3 tools/checks/content_schema.py my_mod                                               # 校验
tools/run_game.sh -- --mods=my_mod --scene=stage36 --skip-movies                     # 开窗口玩示例关
```

- 预期: 校验打印 `内容包 schema 校验: my_mod -> 通过`; 游戏启动日志第一行是 `Content: tdj 1.3.0, remake 1.0.0, my_mod 0.1.0` (实际加载的包, 顺序即覆盖顺序)。
- 无窗口验证 (CI/远程; 无头必须加 `--fixed-fps 25`, 否则按真实时间跑得很慢; 预期输出含 `判定: win`): `tools/godot/godot --headless --path game --fixed-fps 25 -- --mods=my_mod --scene=stage36 --skip-movies --fast --autoplay --god --seed=1 --quit=3000`。
- 想永久启用 (不带命令行): 写 `user://settings.json` 的 `"mods": ["my_mod"]`; **命令行 `--mods=` 优先于设定文件** (`content_db.gd` `_ready`)。

## 第 2 章 manifest.json

最小改动包:

```json
{"format": "tdj-content/1", "id": "my_mod", "name": "我的魔改", "version": "0.1.0", "engine_min": "1.0.0", "base": ["remake"]}
```

| 字段 | 说明 |
|---|---|
| `id` / `version` | `id` = 目录名; `version` 点分数字, 存档会记录 |
| `base` | 依赖包列表 (先加载); 全新游戏 `[]` |
| `stage_count` / `town_count` | 关卡数 / 城镇数 (目录 `stages/00..N-1`、`towns/00..N-1`); 多包时取最大 |
| `ending_movies` | 播完后结束游戏回标题的过场视频号 |
| `start` | **新游戏起点** (见下) |
| `tables` | 声明按键合并的数据表 `{表名: {file, key}}`; 全新游戏要声明 9 张, 改动包沿用基础包的 |
| `asset_roots` | 资源根查找顺序: 包内 `assets/` → `hd4x` → `original`; 全新游戏自带美术时可省略 |
| `save_neutral` | `true` = 只影响表现 (界面/字体), 不记入存档签名 |
| `engine_min` / `engine_max` / `save_compat_min` | 引擎版本范围与存档兼容下限 (第 10 章) |

**起点 `start`**: 缺省 = 第 0 关、金钱取规则参数 `initial_gold` (原版 5)、不播开场过场, 与原版一致。

```json
"start": {"kind": "town", "id": 0, "entry": 0, "gold": 50, "movie": 3}
```

- `kind`: `stage` (进第 `id` 关战场) 或 `town` (进第 `id` 个城镇的入口 `entry`); 城镇里出城/`leave_town` 去 `state.next_stage` (城镇脚本 `set_stage stage=N` 设置, 缺省第 0 关)。
- `gold`: 起始金钱; `movie`: 新游戏时先播的过场号 (按 `Movie_<n>` 查找, 找不到或 `--skip-movies` 时跳过)。
- 多个包都写了 `start` 时后加载的整个替换; 校验 (`content_schema.py`) 会查 `id` 是否在 `stage_count`/`town_count` 内。
- 验证: `python3 tools/checks/content_schema.py --pack game/content/templates/minimal_game --strict` 预期 `通过`; 看实际生效的起点: `python3 tools/checks/content_schema.py --trace-load minimal_game | grep start`。

**加载顺序与覆盖可视化**: `python3 tools/checks/content_schema.py --trace-load my_mod` 打印包的加载顺序、manifest 合并结果 (每个字段由谁提供、谁覆盖了谁)、每张数据表各包增/改/删条数、被后包整文件覆盖的同路径文件、`rules.json` 参数的来源。这是调「为什么我的改动没生效」的第一步。

## 第 3 章 数据表

九张表, 都在 `data/*.json` (营地在 `camps/camps.json`), 每张是**记录数组**, 记录以键字段识别:

| 表 | 文件 | 键 | 作用 |
|---|---|---|---|
| `units` | `data/units.json` | `id` | 单位模板 (体力/移动/五项属性/贴图号/攻击类型/阵营) |
| `items` | `data/items.json` | `id` | 物品 (类型/装备者/攻击防御/售价/使用效果) |
| `skills` | `data/skills.json` | `id` | 绝技与咒术 |
| `levelup` | `data/levelup.json` | `unit_id` | 我方升级成长与技能习得 |
| `party_init` | `data/party_init.json` | `unit_id` | 我方初始状态; **这张表里有的单位才是「我方角色」** |
| `attribute_defense` | `data/attribute_defense.json` | `index` | 属性抗性 (单位的 `attribute_defence_id` 指向这里) |
| `terrain` | `data/terrain.json` | `move_type` | 各移动类型在各地形类别上的移动消耗 |
| `shops` | `data/shops.json` | `id` (字符串) | 商店 (城镇 `town.json` 的 `shops` 按顺序引用, 脚本 `shop id=N` 取第 N 个) |
| `camps` | `camps/camps.json` | `stage` | 各关结束后的营地 (没有记录 = 直接进下一关) |

**改动包的三种操作** (只写要改的记录; `base` 非空时记录只要求键):

```json
// data/items.json: 改 id 0 的售价 / 追加 id 374 / 删除 id 5
[{"id": 0, "price": 30}, {"id": 374, "name": "新剑", "type": 1, "price": 9}, {"id": 5, "_delete": true}]
```

- 子对象深合并: `{"id": 0, "attack_range": {"max": 3}}` 只改 `max`。
- **编号与下标陷阱**: 单位/物品/技能 id = 数组下标 (整数键的表被读成「下标 = 键」的数组)。新增 id 要**接在最后、不跳号** (跳号会留空位并告警); 删除只留空位, 不会让后面的 id 前移。
- 数据表之外你自己加的表 (如 `quests`) 在 `manifest.tables` 声明后同样按键合并, 脚本/代码用 `Content.table("quests")` 读取。
- **全新游戏**的最小集合: 看 `game/content/templates/minimal_game/data/` (2 个单位、1 件物品、空技能表、1 个我方角色、7 行抗性、12 行地形、1 家店、空营地表), 字段含义见 [内容格式.md §5](内容格式.md)。
- 校验: `python3 tools/checks/content_schema.py --pack game/content/my_mod --strict`; 它会查跨表引用 (关卡单位的模板 id、商店物品、城镇引用的商店等)。

## 第 4 章 规则参数 rules.json

包根目录放 `rules.json`, 只写要改的参数:

```json
{"format": "tdj-rules/1", "params": {"turn_limit": 120, "initial_gold": 50}}
```

- 全部参数、类型、默认值与依据见 [规则参数表.md](规则参数表.md) (由 `game/engine/rules/params.gd` **自动生成**, 不手抄): 重新生成 `python3 tools/docgen/params_table.py --write-doc`; 终端查看 `python3 tools/docgen/params_table.py | grep turn`。
- `--strict` 校验参数名与类型, 拼错会给建议。试一下: 把 `turn_limit` 改成 `turn_limt`, 运行 `python3 tools/checks/content_schema.py --pack game/content/my_mod --strict`, 预期报 `未知参数 turn_limt, 你是不是想写 turn_limit`。
- 规则参数影响战斗结算与存档/回归哈希; 改了公式类参数后, 确定性回归的基线要重录。

## 第 5 章 做一关

一关 = `stages/NN/` 下五个文件 + 一个剧情脚本。照着 `game/content/templates/minimal_game/stages/00/` (12x8 的草地, 旅人 vs 野狼) 或 `example_mod/stages/36/` 做; 字段全表见 [内容格式.md §6](内容格式.md)。

| 步骤 | 文件 | 要点 |
|---|---|---|
| 1 地图 | `map.json` | `width/height` + 三个 `height x width` 的整数网格: `terrain` (地形类别 0~9, 查 `terrain` 表的移动消耗; 7 = 步行不可通过)、`floor` (近景战斗地面帧号)、`event` (格子引用 `map_events` 的下标, 0 = 无) |
| 2 图层 | `layers.json` | `backgrounds` 背景图 (`image` = 资源路径, 每格 30 像素, 12x8 格 = 360x240 的 PNG)、`objects` 场景动画物件 |
| 3 单位 | `units.json` | 每个出场单位一条: `index` (本关内的下标, 剧情与胜负条件都用它)、`unit_id` (模板)、`x/y`、`lv`、`ai`、装备/掉落 (`kill_get_*`)、`kill_event` (被击杀时触发的事件号, -1 无) |
| 4 关卡 | `stage.json` | 名字/简报/资源/`turn_events` (哪回合触发哪个事件)/`map_events`/`judge` (胜负条件→事件号)/`script`/`text` 引用 |
| 5 对白 | `text.json` | `groups[事件号][句号]`: 剧情里 `say msg=N` 取**本事件**对白组的第 N 句 |
| 6 剧情 | `scripts/stage_NN.evs` | 语法见第 6 章 |

- **单位默认不在场**: 开场事件里必须 `show ids=0,1` 才会出现 (下标 = `units.json` 的 `index`)。
- 胜负条件: `judge.win/lose` 的 `type` 1 = 敌方全灭、2 = 某下标单位离场; 成立后跑它的 `event`, 事件里用 `end_stage` (进下一关/城镇/营地) 或 `to_title` (回标题) 收尾。**没有收尾指令的胜利事件会让战斗悬着**。
- 关数: 在 `manifest.json` 里把 `stage_count` 改成总关数 (新增第 36 关 → `37`)。
- 进入测试: `tools/run_game.sh -- --content=minimal_game --scene=stage0 --skip-movies` (改动包: `--mods=my_mod --scene=stage36`); 无头代打通关:

```bash
tools/godot/godot --headless --path game --fixed-fps 25 -- --content=minimal_game --scene=stage0 --skip-movies --fast --autoplay --god --seed=1 --quit=6000
```

预期输出含 `判定: win, 事件 2` 与 `结局: 回到标题`。注意 `--god --autoplay` 只证明流程能走通, **不证明正常难度可通关**。

## 第 6 章 剧情脚本 (.evs)

完整语法与执行模型: [剧情脚本格式.md](剧情脚本格式.md); **全部指令的当前列表 (生成, 含参数默认值与标志)**: [剧情脚本格式_指令表.md](剧情脚本格式_指令表.md)。一个脚本是 `script battle|town` + `events N` + 若干 `event K` 块:

```
script battle
events 3
event 1
    camera_set x=4 y=3
    show ids=0,1
    say cursor=-1 face=1 msg=0
    return
event 2
    say cursor=-1 face=1 msg=0
    end_stage next=0
    return
```

- 常用战场指令: `show/hide/fade_out ids=..`、`place/walk_to/move` (演出走位)、`say` (对白)、`camera_set/camera_pan`、`wait frames=N`、`set_var/add_var/if_var` (变量与分支, 跳转用标签)、`end_stage`、`game_over`、`to_title`、`movie id=N`、`music_*`。城镇: `say`、`shop id=N`、`leave_town`、`goto_town town= entry=`、`camp id=`、`give_item`、`has_item`、`choose` (是/否)、`pay`、`set_stage`。
- 单位用关卡内下标 (`unit=`), 角色用角色 ID (`hero=`), 物品用物品 ID (`item=`)。
- **变量约定**: 剧情变量 0~127 供脚本使用, 关与关之间不清零 (关内局部变量请在事件 1 开头 `set_var` 重新赋值)。**引擎保留的号不要写**: 100~102 (最近一次行动者/被攻击者/当前行动单位)、103~106 (召唤标志)、`30 + 关号` (过关回合数); 128 以上的键被离队标志等占用。完整表见 [保留变量表.md](保留变量表.md); `--strict` 校验会对写保留变量/越界变量报错。基于原版的改动包还要避开原版剧情占用的 1~17、80~90 (表里标 `tdj`, 只提示不报错), 全新游戏可自由使用。
- 分支与结局的写法: 参照原版 `game/content/tdj/scripts/stage_31.evs` 里用变量 + `if_var` 跳转的分支结构。
- 语法检查 (编译成原版事件字节码, 不进游戏):

```bash
python3 tools/assets/compile_events.py game/content/templates/minimal_game/scripts/stage_00.evs /tmp/x.COD
```

预期 `/tmp/x.COD: NNN 字节`; 语法错误会指出 `文件:行`。引擎运行时也直接编译 `.evs`, 不需要先转 COD。

- 想加新指令 (比如你的游戏要「天气」)? 步骤见 [指令表文末「新增一条指令的步骤」](剧情脚本格式_指令表.md): 指令只在 `tools/assets/compile_events.py` 的 `OPS` 一处定义, 引擎 VM 登记 handler, 闸门测试 `python3 -m unittest tools/tests/test_evs_ops_gate.py` 保证各处一致。

## 第 7 章 城镇、商店、营地

- **城镇** `towns/NN/`: `town.json` (地图图 `assets.map_image`、`entries` 入口列表 [`x/y` 格坐标、`dir` 朝向、`music`]、`shops` 商店 id 列表、`script`、`text`)、`map.json` (`block` 不可走=1、`talk` 对话事件号、`step` 踩格事件号, 三个 `height x width` 网格, 每格 30 像素)、`layers.json` (NPC/场景动画)、`text.json`。`minimal_game` 的城镇: 12x10, 南出口 `step` 格触发事件 1 (`leave_town`), NPC 格 `talk` 触发事件 2 (一句对白)。
- **商店** `data/shops.json`: `{"id": "town00.0", "type": 0, "keeper": 0, "items": [物品 id...], "keeper_anim": ...}`; 城镇 `shops` 数组按顺序引用它们, 脚本 `shop id=N` 打开第 N 个。
- **营地** `camps/camps.json`: `{"stage": 关号, "town": 城镇号, "town_entry": 入口号, ...}`; `end_stage camp=N` 进营地 N (营地里「出发」进下一关, `town>=0` 时可回城镇)。
- **关卡结束的路由**: `end_stage town=T camp=C next=N`: `camp≠-1` 进营地 C, 否则 `town≠-1` 进城镇 T, 否则直接进第 N 关。
- 试一下: `tools/godot/godot --headless --path game -- --content=minimal_game --scene=rpg0 --skip-dialog --skip-movies --walk-all` (自动走遍每个 NPC/事件格), 预期输出 `走查 城镇 0: 事件 2 个, 起点 (5, 5), 问题 0`。

## 第 8 章 美术与资源

- 内容里只写**资源相对路径**, 如 `Stage/min/map.png`; 引擎按 `manifest.asset_roots` 顺序找: 包内 `assets/` (同构路径, 不区分大小写) → `hd4x/` (高清版) → 原图仓库。后加载的包的 `assets/` 覆盖先加载的。
- 动画 = 一个目录 (内含 `anim.json` 与帧图); 战场地图/城镇地图 = 一张 PNG, 每格 30 像素 (1 倍原版; 高清版由引擎放大)。音乐 `Music/Music_NN`, 过场 `Movie/Movie_NN`, 编号在脚本与 `stage.json` 里引用。
- 界面里用到的贴图用**逻辑名** (`ui_theme/assets.json` 的 `names`, 如 `ui.dialog` → `Misc/MSG_BOX`), 想换界面皮肤只改这个映射并提供图。
- **资源路径存在性检查**: 

```bash
python3 tools/checks/check_assets_refs.py --pack game/content/my_mod
python3 tools/checks/content_schema.py --pack game/content/my_mod --strict     # 同样检查, 并带上其他 strict 项
```

  预期 `[my_mod] 资源引用全部存在`。没有原图仓库时, 不在包内 `assets/` 里的路径无法验证, 只计数提示 (`N 处无法验证`), 不报错。
- 注意: `minimal_game` 目前**借用原版的界面皮肤和角色/关卡贴图** (`asset_roots: ["original"]`, 单位 `sprite` 号、标题卡、战斗地面都指向原图仓库), 只有两张地图 PNG 是自带的。做真正独立的新游戏时, 要把 `ui_theme/assets.json` 与单位 `sprite`/动画目录指向自己的资源并放进包内 `assets/`。
- 大小写: 原版路径大小写不统一, 引擎不区分; 但请在包内保持一致。

## 第 9 章 界面主题

- `ui_theme/layout.json` (布局表: 每个界面元素的位置/文字排版/贴图)、`fonts.json` (字体清单)、`assets.json` (资源逻辑名); 演出定位在 `fx/cast.json`、`fx/cutscenes.json`。**改动包只写差异**: 同路径文件逐元素叠加 (`example_mod/ui_theme/layout.json` 就是只改了对话框文字偏移与近景名字颜色); **全新游戏要自带这三个文件** (`minimal_game` 直接复制了 remake 的, 再改)。
- 布局表结构、继承与覆盖规则、新界面如何接入:。
- 调布局: `tools/run_game.sh -- --layout-debug` (叠加元素边框/名字, 校对工具)。
- 验证: `python3 tools/checks/layout_stats.py --check` (布局表统计与元素一致)。

## 第 10 章 存档与版本

存档记录 `content: [{id, version}]` (主包与全部叠加包) 和引擎版本; 读档时逐包比对, 规则全表见 [内容格式.md §3.1](内容格式.md)。作者要决定的是: **这次改动要不要升版本号、要不要抬 `save_compat_min`**。

| 你改了什么 | `version` | `save_compat_min` |
|---|---|---|
| 只改文案、对白、美术、界面布局 (不影响存档里的数值/编号) | 升补丁位 (0.1.0 → 0.1.1) | 不动 |
| 加关卡/物品/单位 (只追加, 旧编号含义不变) | 升小版本 (0.1.x → 0.2.0) | 不动: 旧档仍能读, 读入后提示「已从 vX 升到 vY」 |
| 改了旧档会引用的东西的含义: 物品/技能/单位 id 重新编号或删除、party_init 角色增删、剧情变量用途改变、关卡顺序/数量变化 | 升大版本 (0.x → 1.0.0) | **抬到新版本**: 低于它的旧档读档被拒绝并提示过旧 |
| 引擎格式不兼容 (指令集变化等) | — | 抬 `engine_min`, 版本范围外的包不加载并报 `Content:` 错误 |

- `save_neutral: true` 只用于纯表现包 (界面皮肤、字体、演出), 它不进存档签名, 也不参与比对。
- 目前没有数据迁移钩子: 升级后旧档里指向已删/改号数据的部分只能靠 `save_compat_min` 整体拒绝, 所以**编号一经发布不要改动**。
- 规则: 存档里的我方角色键 = 单位编号, 与 `party_init` 表一致; 新游戏角色超过 10 人时请自己验证存读档往返。

## 第 11 章 测试你的包

1. **静态**: `python3 tools/checks/content_schema.py --pack <目录> --strict` (秒级, 不需要原版; CI 里 `tools/ci.sh fast` 的 content-schema 步骤就是 `--strict`)。
2. **无头代打**: 第 5 章的命令; 看日志里 `判定: win`、无 `SCRIPT ERROR` / `ERROR:`。
3. **无头单元测试** (GDScript): 仿 `game/tests/test_content.gd` 的 `test_example_mod_stage_loads` / `test_minimal_game_template` —— `ContentDB.new().load_packs([...])` 后断言关卡/表/起点。运行: `tools/godot/godot --headless --path game --script res://tests/run_tests.gd -- test_content`。
4. **Python 端到端**: 仿 `tools/tests/test_minimal_game.py` (strict 校验 + 无头新游戏进入起点 + 打通第 0 关); 运行 `python3 -m unittest tools/tests/test_minimal_game.py`。

## 第 12 章 调试

| 现象 | 办法 |
|---|---|
| 改动没生效 / 不知道谁覆盖了谁 | `python3 tools/checks/content_schema.py --trace-load my_mod` (加载顺序、字段/表/文件/参数的来源与覆盖) |
| 字段拼错被静默忽略 | `--strict` 的「未知字段 x, 你是不是想写 y」 |
| 规则参数不生效 | `--strict` 查参数名与类型; 对照 [规则参数表.md](规则参数表.md) |
| 贴图/动画/音乐缺失 | `python3 tools/checks/check_assets_refs.py --pack ...` |
| 剧情里变量行为怪 | 是不是写了保留变量: [保留变量表.md](保留变量表.md); `--strict` 会报 |
| 脚本语法错 | `python3 tools/assets/compile_events.py X.evs /tmp/x.COD` 报 `文件:行` |
| 看战斗里每次攻击/AI 决策 | 游戏参数 `--ai-trace` (对照追踪, 打印每次普攻交换) |
| 界面元素位置不对 | `--layout-debug` |
| 帧率/内存 | `--perf-log=<文件>` 退出时写 JSON |
| 启动即回标题并提示「场景加载失败」 | 看日志里 `Content:` 与 `场景加载失败, 回标题:` 行, 通常是缺文件 (`stages/NN/stage.json`、`towns/NN/town.json`) 或 `stage_count` 写小了 |

常见错误信息: `找不到内容包 X` (id 与目录名/`base` 不符, 或没放进搜索目录); `循环依赖` (`base` 成环); `manifest 不是 tdj-content/1`; `引擎版本不满足` (`engine_min/max`); `.evs` 编译错误带 `文件:行`; `未知参数 x` (rules.json 拼错)。

## 第 13 章 分发

- 做好的包整个目录放进玩家目录 `user://content/<包名>/`, 再 `--mods=<包名>` 或写 `settings.json` 的 `mods` 启用; 没有游戏内的内容包管理界面。
- 依赖声明靠 `base` 与 `engine_min/max`; 依赖原版内容的改动包 (`base: ["tdj"]`) 要在说明里写明玩家需先用自己的原版游戏生成 `tdj` 包。
- **不要分发**: 原版游戏文件、从原版截图/提取的素材、`game/content/tdj/` 的内容、原作对白原文; 只分发你自己的数据与原创素材 (红线见根目录 `CONTRIBUTING.md`)。
