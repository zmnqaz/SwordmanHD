# 剧情脚本格式（.evs）

原版剧情是字节码 `EVENT_NN.COD`（战场 `Stage/StageNN/`，城镇 `Rpg/rpgNN/`）。按《架构设计》第 0 节第 3 条，
复刻引擎不再读 COD，而是执行本文定义的可读脚本 `.evs`：现有脚本随基础内容包生成，行为与原版一致；新剧情直接手写或修改脚本。

| 项 | 位置 |
|---|---|
| 脚本 | `game/content/tdj/scripts/stage_NN.evs`（36 关，00~35）、`town_NN.evs`（27 城镇，00~26） |
| 对白表 | 内容包 `stages/NN/text.json`、`towns/NN/text.json` 的 `groups`（来源 `data/emsg/`），组号 = 事件号 |
| 编译 | `python3 tools/assets/compile_events.py X.evs X.COD`：检查语法并编译一个脚本 |
| 指令表 | `tools/assets/compile_events.py` 的 `BATTLE` / `TOWN`（唯一定义，本文第 4 节由它生成） |
| 引擎执行 | 载入关卡/城镇时 `game/engine/script/evs_compiler.gd` 把 `.evs` 编译成与原版字节码逐条相同的指令，交给 `EventVM` / `RpgVM`；指令表 `game/engine/script/evs_ops.json` 由 `compile_events.py --export-ops` 导出（`tests/test_content.gd` 对照脚本） |

依据：对照原版的实际行为, 命名参考了已有的开源重制项目。

---

## 1. 一个例子

（取自 `stage_00.evs` 事件 1 开头，末尾的分支是为演示标签补写的。）

```
script battle
events 20

event 1
    movie id=0
    music_load music=50 ch=1
    camera_set x=14 y=4
    say cursor=-1 face=24 expr=2 msg=7    # 「这夜魑太难对付了！／大家一拥而上，合力打倒它！」
    show_group group=5 effect=1
    move_steps steps=3 speed=2 {
        walk_dir unit=0 dir=2
        walk_dir unit=5 dir=2
    }
    if_var var=9 cmp=eq value=1 goto=L1
    set_var var=10 value=1
    goto to=L2
L1:
    give_item item=174
L2:
    return
```

## 2. 语法

文本文件，UTF-8，一行一条。缩进不影响含义（解析输出用 4 格缩进）。

| 写法 | 含义 |
|---|---|
| `# ...` | 注释，到行尾（引号内的 `#` 除外）。解析时对白原文、异常说明写在注释里。 |
| `script battle` / `script town` | 必须有。决定指令表：战场（``）或城镇（``）。 |
| `events N` | 事件槽数。省略时取原版固定值：战场 20，城镇 65。COD 里事件按槽号索引，空槽也要占位。 |
| `event K` | 开始第 K 号事件，直到下一个 `event` 或文件结束。没写的事件为空事件。事件号的用途由关卡数据决定：回合事件 TEVT、地图事件 MEVT、单位的 kill_event、胜负 JUDGE 都按号引用。 |
| `名字:` | 标签，写在事件内、块外，指向下一条命令；写在事件末尾则指向事件结束处。标签只在本事件内有效。 |
| `命令 参数=值 ...` | 一条命令。参数顺序任意。 |
| `命令 参数=值 ... {` 换行 若干记录 换行 `}` | 批量命令（`move`、`move_steps`），块内只能写对应的记录命令，块不能嵌套。 |

**值**：整数（十进制、负数、`0x` 十六进制）；标签名（只用于跳转参数 `goto=`/`to=`）；
符号（`cmp=eq|gt|ge|lt|le`，`group=player|npc|enemy`）；列表 `ids=1,2,3`（逗号分隔，无空格）。

**默认值**：第 4 节参数栏里写了 `=值` 的参数可以省略，省略即取该值；没写默认值的参数必填。
解析时与默认值相同的参数不写出。

**跳转**：`goto to=标签`、`if_var ... goto=标签`。原版字节码里存的是目标指令的序号（int32），
编译器按标签位置换算（批量命令按展开后的条数计）。为了无损，也允许直接写整数序号；
解析遇到越界序号（原版数据里有 2 处）就原样写数字并加注释。

**对白**：`say ... msg=N` 指对白表里**本事件号那一组**的第 N 句（原版规则：EMSG 组号 = 事件号）。
城镇 `choose ... msg=N` 依次用第 N、N+1、N+2 句作为问题、「是」、「否」。解析在行尾注释附简体原文，`／` 表示换行。
新剧情照此在对白表里加句子即可，不需要改格式。

**raw**：`raw op=0x47 data=0a000900` 原样写一条字节码（类型号 + 参数字节的十六进制），给未知指令或参数长度不符的情况兜底。
现有 63 个脚本里没有用到。

### 2.1 批量命令

原版有 5 条「头指令 + N 条记录」形式的指令：头指令给出条数 N，解释器在**同一帧内**把后面 N 条指令当作记录逐条读取
（不看记录的类型号，只读参数）。脚本把它们合并成一条：

| 原版 | 脚本 | 说明 |
|---|---|---|
| `0x0B N` + N×`0x01 unit` | `show ids=a,b,c` | 单位出场 |
| `0x0A N -1` + N×`0x01` | `hide ids=a,b,c` | 单位立即离场 |
| `0x0A -1 g` | `hide group=player\|npc\|enemy` | 按类别全部离场：0 玩家单位（阵营 0、字段=0），1 友军 NPC（阵营 0、字段=1），2 敌人（阵营 1） |
| `0x09 N -1` + N×`0x01` / `0x09 -1 g` | `fade_out ids=...` / `fade_out group=...` | 同上，但淡出且阻塞到淡出结束 |
| `0x0E N start follow speed` + N×`0x0F` | `move start= follow= speed= { walk_to ... }` | 一批单位同时走，全部走完才继续 |
| `0x10 N start follow steps speed` + N×`0x11` | `move_steps steps= ... { walk_dir ... }` | 一批单位同时朝某方向直走 steps 格 |

不满足合并条件时（记录条数不足、类型不对、或有跳转落在记录中间），解析写成头命令带 `count=N`，
后面的记录各自成行（`unit_ref`、`walk_to`、`walk_dir`），并加注释。引擎必须按原版语义执行：头命令之后的 N 条指令无论类型都当作记录读。
数据里只有 1 处（第 29 关，见 5.3）。

## 3. 执行模型（引擎实现要点）

- 一个事件是一串命令，从第 0 条顺序执行，`return` 或执行到末尾结束。跳转目标 ≥ 指令数也等于结束。
- 每帧解释器连续执行非阻塞命令，直到遇到阻塞命令（镜头平移、对白、动画、移动、淡入淡出、`wait`、`next_frame`）才让出这一帧。
- 同一时间只执行一个事件；执行中又触发的事件排队（重制版 eventList，原版待核）。
- 剧情变量 `var` 是 128 个 int32，新游戏时清 0，关卡切换和读档都不清；变量含义见 第 1 节
  （100 最近行动者、101 被攻击者、102 当前行动单位、30+关号 过关回合数；1~7 多为图层物件显示开关：LAYER 物件 `effect` 字段 ≠-1 时，`var[effect]≠0` 才显示）。
- 单位用关卡 MAN 表下标（`unit=`），角色用角色 ID（`hero=`），物品用物品 ID（`item=`）。
- 城镇的 `goto_town`、`shop`、`leave_town`、`camp` 执行后**本事件立即结束**（原版返回 1）。

## 4. 命令表

> 当前代码里指令表的**生成版**见 [剧情脚本格式_指令表.md](剧情脚本格式_指令表.md) (含让出帧/切场景标志与「新增一条指令的步骤」); 下面的表保留原版出现次数等历史统计, 指令增删以生成版为准。

「次数」是该指令在全部 63 个原版脚本里出现的次数（批量命令的记录单独计数），「—」表示原版数据没用到，
但解释器里有实现（参数按对照原版读取的偏移定长度），编译器支持。参数类型默认 int16，`:i32` 为 int32，`:标签` 为跳转目标（int32）。

两套指令表**同名命令语义相同**（如战场 0x25 与城镇 0x15 都是 `obj_show`），引擎可共用实现。

### 4.3 参数补充

- `say`（战场）：`unit` 为 -1 时不移光标；否则光标移到该单位，`cursor=1` 时平滑移动并等到位，其它值立即跳过去。
  `face` 头像号，`expr` 表情，`pos` 对话框位置（数据里有 -1、0、1、10）。城镇 `say` 的 `u0~u2` 引擎不读（只读 +6 起的 4 个参数）。
- `walk_to`：走直角折线，不寻路。`vfirst=0` 先沿 x 走到目标列，再沿 y；`vfirst≠0` 先 y 后 x。
- `move`/`move_steps`：`follow≠0` 时镜头只跟随块内**第一个**单位；`start` 传给每个单位的移动（含义待查）；`speed` 移动速度档。
- `walk_dir`：`dir` 0 北 1 南 2 西 3 东（重制版注释；方向编码待与 `face`/`place` 的 `dir` 统一核对）。
- `screen_fade`：`color` 为 RGB555；`mix_*` 是混色量从 from 到 to、每次变化 step，`light_*` 是亮度同理（0~16），每 `delay` 帧变一次。
  `fade_to_black delay=d` 等于 `screen_fade color=0 light_from=16 light_to=0 light_step=2 delay=d`，`fade_from_black` 为 0→16。
  渐变结束后遮罩仍在，由 `screen_clear` 撤掉。字段命名按代码结构推断，具体混色公式待核。
- `anim_play`：`sound` 是 int32，数据里都是 10000000+n 形式（如 10000002），存到动画槽 字段，用途待查；`from=-1` 表示从头到尾。
- `set_ai`：五个 int16 依次写单位 字段；`ai` 类型与 `p1`~`p4` 的含义（重制版：移向单位时 p1/p2 为目标，移向格时为 x/y）。
- `end_stage`：camp 优先于 town；两者都为 -1 时直接进 `next` 关。
- `show_group`：`effect=1` 时每个单位出场前调用 （出场演出）。
- `choose`（城镇）：5 个 int16，`a0~a2` 在数据里固定为 1、0、0。

## 5. 写新脚本的约定

- 直接编辑或新建 `.evs`，引擎直接读 `.evs`。
- 只用第 4 节的命令；新机制需要新命令时，在 `tools/assets/compile_events.py` 的指令表里加一条（指令号取 0x57 以后，战场/城镇分别编号），
  运行 `python3 tools/assets/compile_events.py --export-ops` 更新引擎的指令表，在 VM 里实现，并在本文登记。
- 对白一律走对白表，`msg` 只是编号；新增对白在对白表对应组里追加。
- 标签名用有意义的名字（如 `has_herb:`），自动生成的 `L1`、`L2` 标签可以随手改名，编译结果不变。
