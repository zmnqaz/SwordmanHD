# 通关录像 (录制自己的通关, 之后原样回放)

## 用法

- **录制**: 默认自动录 (有窗口的正常游玩; headless / 自动测试 / 回归不录)。从启动 (标题画面) 开始, 每 10 秒和退出时保存到用户目录 `replays/play_<日期时间>.json` (Godot `user://replays/`)。
  - `--record-play=<路径>` 指定文件; `--no-record-play` 关闭。
- **回放 (命令行)**: `--replay-play=<文件> [--replay-speed=N]`。从标题画面开始, 同一套内容; N 倍速 (Engine.time_scale)。
- **回放 (菜单)**: F1 (F10) 设定面板 (触屏右上角「设置」钮 / 手柄 Start) →「录像回放」→ 选一份录像 (↑↓), ←→ 选倍速 (0.5x / 1x / 2x / 4x / 8x / 16x), 确认开始。Windows / 手机没有命令行时用这个。进程内直接切到回放, 不重启: 当前游戏状态丢弃 (正在录的先存盘), 起点与命令行回放完全一样。
  - **回放期间屏蔽真实输入** (回放锁): 键盘、鼠标 (含移动)、手柄、触摸都不再进游戏, 免得真实操作混进回放的指令流、打乱后面的操作。只放行能打开设定面板的: F10 / 手柄 Start / 触屏「设置」钮; 设定面板开着时输入照常给面板。F3 (跳过对白)、M (战场地图) 等也被屏蔽。放完或「结束回放」后解锁。实现: `InputRouter.replay_lock` (`_handle` 开头吞掉, `_replay_passes` 放行设定入口), `PlayLog` 回放开始/收尾时置位/清除。
  - 回放中开 F10: 回放与游戏时间一起**暂停**; 设定面板多出两行:「回放速度」(←→ 随时调, 立即生效) 和「结束回放」(回标题)。
  - 回放期间存档写到 `user://replay_saves/` 沙盒, **不会覆盖真实存档**, 放完 / 结束后恢复真实目录。
  - 放完提示「回放结束」, 停在录像终点的状态, 可以接着手动玩并**接着录**: 新开一份 `play_<日期时间>.json`, 里面是放过的整段 + 之后手动玩的。「结束回放」回标题后同样重新录一份 (从标题画面起录, 文件 meta 里 `title_start`, 回放它直接进标题、不放 logo 动画)。
- 目录: Windows `%APPDATA%\SwordmanHD\replays\`, Linux `~/.local/share/SwordmanHD/replays/` (Godot `user://replays/`)。
- 窗口大小应与录制时相同 (鼠标/触摸动作带视口坐标, 不同会警告); 菜单回放同样。

## 单幕战斗录像 (通关一幕自动出一份)

每打完一幕 (胜利), 自动导出 **这一幕从开战到通关的战斗录像** `replays/stage_NN_<日期时间>.json`: 起点 = 这一幕开战前的游戏状态 (嵌在文件里), 内容 = 这一幕里的全部操作 + 每场战斗的种子, **中途无论读了几次档 (战阵重现、读存档重进), 放弃的段都已剪掉**, 留下的是最后那条顺利通关的路线。失败 (战败) 不导出; 读的是本幕开战之前的档则本幕作废, 重新进关会重新记。
回放: `--replay-play=<stage_NN_….json>`, 直接从该幕开战前的状态进战场, 把操作原样放一遍。整场游玩的总录像 (`play_*.json`) 仍然同时保留。

## 读档剪辑 (只留顺利的路线)

录像记下每次存档 (营地/城镇存档位、战阵存录) 的位置。读档时:
- 存档是**本次录像中存的** → 把存档之后被放弃的操作/战斗种子/检查点剪掉, 从存档点接着录; 最后通关时录像就是「从开始到通关、读档放弃的段全剪掉」的那条路线。
- 存档是**之前某次启动存的** (关了游戏、下次启动再读档接着玩) → **接上那次的录像历史**, 录像仍然是从游戏开头到现在的整场 (见下节)。
- 存档**没有录像历史** (录像功能出现之前存的老档、录像关着时存的、历史文件被删) → 录像清空, 以这个存档的内容作为录像起点 (回放时先读入它), 之前的全部省掉。

### 跨次启动: 存档带着录像历史

- 录像中存档时, 存档文件里写一个 `replay_id`, 并在存档旁边写 `<存档文件>.replay` (zstd 压缩的 JSON: 到这一刻为止的全部操作、战斗种子、检查点、起点)。存档位 `save1.json` 旁边是 `save1.json.replay`, 战阵存录 `battle.json` 旁边是 `battle.json.replay`。历史文件随存档重写, 压缩后一般 ≤ 几 MB。
- 读档时存档里的 `replay_id` 和旁边历史文件里的 id 对得上就接上; 对不上 (存档被录像关着时覆盖了、历史文件缺了/坏了、读的是 `.bak`、存档拷到别处没带 `.replay`) 退回上面第三种。
- 连续多次启动、每次都读上次的存档接着玩, 历史一路接下去; 每次启动仍然写一份新的 `play_<日期时间>.json`, 里面已经是整场。
- 没有历史的存档救不回来: 第一次读它仍然从这个存档开始, 之后再存的档才带历史。想要从第一幕起的整场录像, 要从新游戏开始一路玩, 且存档/战阵存录和旁边的 `.replay` 一起保留。
- 战阵存录读档时, 单幕录像的起点接在历史之后 (不会把历史算进单幕)。
- 放完回放或「结束回放」后会接着录 (`PlayLog.continuation` / `PlayLog.fresh`, `Game._on_replay_finished` / `stop_replay`), 所以其后存的档仍带 `replay_id`。

### 怎么看录像是不是整场

- **回放列表**每份录像底部说明末尾写起点: 「整场 (从标题开始)」/「从存档开始 (该存档之前没有录像)」/「从战阵存录开始 (…)」/ 单幕「从这一幕开战前开始」。列表里「第 N 幕」(单幕) 排在「整场游玩」前面, 别选错。
- 读入没有历史的存档那一刻会弹提示「读入的存档没有录像历史, 本次录像改为从这个存档开始 (不是整场)」 (`PlayLog.start_replaced` → `Game._toast`)。

## 随机数

每次**进入战场 (创建战斗)** 用当前时间生成一个种子, 整场战斗的命中/闪避/暴击都从这一个随机数流抽 (不是一关一个)。读档 (战阵重现 / 读存档重新进关) 会重新创建战斗、换新种子, 所以读档后必杀/闪避和上次不同 (原版行为)。录像按顺序记下每次实际用的种子 (`seeds`); 读战阵存录换的新种子记在 `load` 事件上, 回放到该点时调 `PlayLog.reseed_hook` 换成当时的。

## 对不上检测

战斗每回合开头记一个检查点 (关号 + 全场血量合计), 回放时逐个比对, 对不上打印一次警告 (之后仍继续放)。

## 实现

- 菜单回放: `engine/ui/replay_panel.gd` (ReplayPanel, 继承 SettingsPanel, 列表/倍速) → `SettingsPanel._activate` → `SceneFlow.start_replay` → `Game.start_replay` (与 `boot()` 共用 `_enter_replay_base` / `_enter_title_flow`)。`PlayLog` 提供 `open_replay` / `stop_current` / `set_speed` / `replaying`, 设定行见 `SettingsSchema` (`replay` / `replay_stop` / `replay_speed`, 后者 kind `live` 不进设定文件)。测试钩子 `--replay-switch=<文件>`: 启动 1 秒后走同一入口切到回放 (无头验证用)。
- `engine/core/play_log.gd` (PlayLog): 订阅 `InputRouter.dispatched` 录动作 (UiAction: kind/echo/pos/delta/source + 录像时钟), 回放时按时钟把同样的动作送回 `InputRouter.dispatch`。
  模态浮层 (F10 设定面板、F4 攻略面板) 开着时的动作不录: 它们不影响游戏, 回放时没有浮层, 录了会落到游戏里。
  例外: 攻略面板的「整理行囊」改了行囊顺序, 之后按格下标选物品的操作要对得上, 所以整理成功 (位置有变) 时 `PlayLog.note_bag_sort` 单独记一条 `{"t", "bag_sort": 1}` 事件, 回放到这里调 `PlayLog.bag_sort_hook` (game.gd 登记, 内容 = `CampInventory.resort_bag`) 再整理一次。
- 存档带历史: `PlayLog.begin_save()` (写存档前发 id) / `note_save(kind, key, 存档路径)` (写 `.replay`) / `note_load(…, 存档路径)` (读档时对 id 接上); `GameSaves._snapshot` / 四个入口调用。
- 钩子: `BattleRules.battle_seed()` (记种子/取种子)、`GameSaves` 四个入口 (存槽/读槽/存战阵/读战阵)、`BattleFlow` 每回合检查点、`Game._ready` 创建并注入 InputRouter、`Game.boot` 回放起点是存档时先读入。
- 测试: `tests/test_play_log.gd` (录制顺序、读档剪辑、老档作起点、种子顺序、跨次启动接历史、连续三次接成一条、id 对不上/历史缺失退回、`GameSaves` 存读往返)。

## 限制 / 未验证

- 依赖游戏逻辑只由输入和战斗随机数决定; 动画时序按录像时钟还原, 极端慢机/卡顿下可能有细小偏差 (检查点会报警)。
- **没有用真人完整通关做过端到端验证** (只有单元测试覆盖录制、剪辑、回放顺序); 首次实际使用请先录一小段 (比如第 0 幕) 回放确认一致。
- 录像不含存档内容本身 (除「老档作起点」时嵌入); 回放用的是同一套内容/资源。
