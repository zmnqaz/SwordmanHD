# 复刻版代码框架设计（设计与现状）

## 0. 三个版本的路线（决定框架怎么搭）

| 版本 | 内容 | 对框架的要求 |
|---|---|---|
| 第一版：完美复刻 | 原版剧情、数值、界面、操作一模一样 | 引擎 + 「原版内容包」 |
| 第二版：魔改 | 在原版上改数值、剧情、关卡、规则、界面 | 内容包可以被「改动包」覆盖，不改引擎 |
| 第三版：全新原创 | 全新剧情、地图、角色、美术 | 换一个全新的内容包，引擎照用 |

所以这套代码是**引擎**，不是「天地劫复刻程序」。由此得出几条硬约束：

1. **引擎与内容分离**：引擎代码里不出现任何原版专属的东西，比如关卡号、单位编号、Misc 文件名、第 31 关特判。
   这些都放进内容包的数据和脚本里。原版里的特例（如第 9 关「鄲陰之外全灭」、第 31 关封印格）用通用机制加数据表达。
2. **内容用我们自己的格式**：原版二进制（COD、DAT、DTL、MAN、MSG、SAF）由导入工具一次性转成我们的格式
   （JSON 或 Godot 资源）。运行时引擎不再读原版二进制，新内容也能用同样的格式手写或用编辑器制作。
3. **剧情脚本可读可写**：原版事件字节码解析成可读的脚本格式（命令名加参数），引擎执行这种格式。
   第一版由导入工具从原版生成，行为与原版一致；第二、三版直接写脚本。
4. **规则可配置**：伤害、命中、成长、AI 等公式集中在规则模块，默认参数等于原版；内容包可以覆盖参数或换公式。
   规则模块在 `game/engine/rules/`，参数集中在 `params.gd`，内容包/改动包根目录的 `rules.json` 按加载顺序覆盖（见 `game/engine/rules/README.md`）。
   内容包加载层在 `game/engine/content/content_db.gd`（autoload `Content`，接口见 `docs/内容格式.md` §14、做改动包见 §15）；
   剧情 `.evs` 由 `game/engine/script/evs_compiler.gd` 在载入时编译执行。
5. **界面可换皮**：界面组件的贴图、坐标、字库来自内容包的「界面主题」。原版主题就是 Misc 素材加 Tfont 字库，乘 4 倍坐标。
6. **内容叠加（Mod）**：加载顺序为基础内容包加若干改动包，同名数据、资源、脚本后加载的覆盖前面的。
7. **存档带版本与内容包标识**，规则或数据变了也能识别、迁移旧存档。

## 1. 第一版的目标

先**操作与画面与原版一致**，再考虑优化。为此代码按原版的系统划分来组织，
每个系统的规则、坐标、帧号尽量对照原版实际行为，重制版 foxgame/Sword 只作参考。

## 2. 系统划分

代码按原作的系统划分来组织: 程序框架、文字、对话框、标题、战场 (关卡、单位、界面、规则、演出)、物品与装备、城镇与商店、剧情脚本、营地、存档、结束。具体模块见 §4。

## 3. 迁移前的问题

早期 `game/scripts/` 是边看边补的（界面各画各的、按键处理分散、战场控制器过大、数据与显示不分、原版依据零散），已在 §5 的迁移中全部解决；现行结构见 §4、§6、§7。

## 4. 目标框架

工程分两层：

```
game/
  engine/      引擎: 与具体游戏无关 (下面各模块)
  content/
    tdj/       原版内容包: 数据 (JSON)、剧情脚本、界面主题、资源路径映射 (贴图仍在 hd4x/ 与原图仓库)
    mods/      改动包 (第二版)
```

引擎模块：

```
game/engine/
  core/        GameState（全局状态）、GameSaves（存档位/战阵存录）、SaveFile（读写/迁移）、GameContext（规则/内容/设置注入）、
               SceneFlow（场景流转）、ResPacks（资源包挂载）；Game（autoload）在 game/scripts/game.gd
  content/     ContentDB（内容包加载与 mod 深合并）、ContentCompat（存档/内容版本兼容）
  rules/       规则引擎 (纯逻辑、不依赖 Node、可无头测试): 属性/伤害/攻击/技能/状态/成长/经验/AI/移动/物品/胜负，
               参数全在 Params (内容包 rules.json 可覆盖); 说明见 engine/rules/README.md
  input/       InputRouter：统一键位 + 模态界面栈，同一时刻只有栈顶收按键；KeyRepeat（方向键按住节拍）、触屏手势/虚拟键
  ui/          原版样式组件：Panel、IconMenu、ListMenu、MsgBox、ChoiceBox、DialogBox、InfoBar、DigitText、……；camp/ 为营地子界面组件；
               布局数据来自内容包 ui_theme/layout.json（锚点见 §6）
  script/      EvsCompiler（.evs → 指令）+ ScriptVM 基类（指令注册表，`register_op` 供 mod 追加）+ evs_ops.json（指令表）
  battle/      战场: BattleScene/BattleStage/BattleView/BattleUI（表现）、BattleFlow（回合流程/阶段/回合事件）、
               BattleRules/BattleActions（规则适配与玩家动作）、BattleUnit、EventVM（战场剧情指令）、control/（玩家操作状态机，每个状态一个类）
  rpg/         城镇: RpgScene/RpgStage/RpgVM（地图、行走、NPC、城镇事件、商店入口）
  camp/        营地菜单、行囊、炼化、装备、五魂、存读档（CampScene + ui/camp 组件）
  fx/          演出: 过场/视频（Cutscene）、法术演出（CastFx）、落点特效（FxPlace）
  render/      Assets（资源逻辑名 → 贴图）、TextureSource、SceneMusic、hq/（运行时 6 倍高清着色器）
  settings/    SettingsSchema（设定面板的数据驱动 schema）
  test/        测试与调试: RegressLog（确定性回归记录）、BattleTestHooks（战场开场注入/测试回合开关）
game/scripts/  Game（autoload）、GameFlow、Main、TitleScene（片头/标题）、MovieScene、AnimPlayer、Autotest、Monkey 等入口
game/content/  内容包: tdj（原版）、remake（重制版复刻 fx 数据）、example_mod（mod 样例）; manifest 见 内容格式.md
```

原则：

- **原版优先**：界面坐标、帧号、公式、操作逻辑以原版实际行为为准，其次重制版，最后才自定。
- **一个画面就是一个界面状态**：只处理四种输入（确认、取消、方向、查看），由 InputRouter 分发；取消键的退回路径在状态里写死，不靠全局判断。
- **数据与表现分离**：规则和数据层不依赖 Node，可以无头测试；表现层只读状态。
- **界面只用原版素材和原版字库**，高清版是同一套坐标乘 4。
- **测试开关集中在 Debug**：`--skip-dialog`、`--god`、`--autoplay` 等，正式流程里不散落测试分支。命令行只在 `DebugArgs`（`engine/core/debug_args.gd`）解析一次，存 `GameContext.debug`，引擎只读字段；规则层不读，开关由战场层注入（如 `AI.trace_cands`）。

## 引擎与 autoload 的边界

autoload（`Game`、`Autotest`、`Assets`、`Content`…）是全局名字，容易让引擎靠名字绕过目录分层（engine 依赖 scripts），战斗/城镇场景也没法在无场景树的测试里独立创建。做法：

| 项 | 做法 |
|---|---|
| 上下文对象 | `engine/core/game_context.gd`（`GameContext`，RefCounted）：`state`（GameState）、`settings`、测试开关 `fast/autoplay/god/skip_dialog/skip_movies`、`debug`（DebugArgs，命令行参数只读）、`battle_resume`、`cur_rpg/prev_rpg`、`flow`。无任何 autoload 依赖，可直接 `new()` |
| 场景流转接口 | `engine/core/scene_flow.gd`（`SceneFlow`）：`goto_rpg/goto_battle/goto_camp/leave_camp/stage_over/game_over/ending/return_to_title/save_game/load_game/save_battle/load_battle/apply_settings/save_settings/is_current`。缺省实现空操作；真实实现 `scripts/game_flow.gd`（`GameFlow`）转给 autoload `Game` |
| 注入方式 | 解释器、场景、界面组件的成员 `var gc: GameContext = GameContext.current()`；组装层 `Game.goto(scene)` 把自己的 `ctx` 显式交给场景（`scene.gc = ctx`），`ScriptVM._init(scene)` 跟随所属场景的 `gc`；测试直接 `x.gc = GameContext.new()` 换独立上下文。静态函数用 `GameContext.current()`。没人装过时 `current()` 惰性建空上下文 |
| `Game` 的角色 | 只做组装：持有 `ctx`，`state/settings/fast/god/…` 是转发到 `ctx` 的属性（scripts/、tests/ 里的旧写法 `Game.state` 不变）；场景切换、淡入淡出、设置应用、音频与窗口仍在 `Game` |
| 测试驱动 | 生产代码不再引用 `Autotest`：日志里的帧号读 `RegressLog.log_frame`（`Autotest` 每帧写入） |
| `make_label` | 迁入 `UiText.make_label`（`Game.make_label` 转发） |
| `Assets` | `scripts/assets.gd` → `engine/render/assets.gd`，autoload 名不变（`project.godot` 改路径），所有 `Assets.` 引用不用动 |
| 平台判断 | 手机/iOS/Android/导出版统一问 `Platform`（`engine/core/platform.gd`：`is_mobile/is_ios/is_android/is_exported`），不再散写 `OS.has_feature`；缺资源包时「包放哪」的提示由 `ResPacks.missing_hint()` 按平台给（文案 `boot.missing.*`，内容包没加载时用后备文字），`Game.resource_error` 只显示。Android 包名三处（导出预设、`ResPacks.ANDROID_PACKAGE`、`build_android.PACKAGE`）由 `tools/tests/test_package_ids.py` 校验一致 |
| 闸门 | `tests/test_engine_deps.gd`：①engine/ 禁止 `Game.`/`Autotest`（白名单 `ALLOW`，现为空）；②`engine/rules`、`engine/script` 禁止任何 autoload；③`Assets/Content/ScreenLayout/InputRouter/ResPacks` 引用数只减不增（`CEILING`）；④按字符串取 autoload 节点（`get_node_or_null("Content")`、`get_node("/root/InputRouter")`）存量登记 `NODE_ALLOW`，只减不增；⑤engine/ 引用 scripts/ 里的 `class_name`（`AnimPlayer`、`MovieScene`…）存量登记 `SCRIPTS_CLASS_ALLOW`，只减不增（这两个类以后搬进 engine/ 即清零）；⑥`OS.get_cmdline_user_args()` 在 engine/、scripts/ 里只许出现在 `DebugArgs`；rules 不引用 `DebugArgs/GameContext`；另有「解释器在注入上下文上运行、不碰全局」的测试 |

遗留：`Content/ScreenLayout/InputRouter/Assets` 仍是 engine 内的全局名（`engine/core/save_file.gd`、`game_saves.gd` 用 `Content`），逐步改注入；`GameContext.current()` 是服务定位器式的缺省，真正的多上下文（多存档并存）需要场景创建时全程显式传递。

## 内容包版本与存档兼容

| 项 | 做法 |
|---|---|
| 缺省主包 | 不再写死 `"tdj"`：`content/content.json` 的 `main` 决定（`ContentDB.default_main()`，无配置取第一个无 base 的包）。唯一保留的 `tdj` 字面量是 `ContentCompat.LEGACY_PACK_ID`：没有 `content` 字段的旧存档确实只可能来自原版包（历史事实） |
| manifest 新字段 | `engine_min/engine_max`（要求的引擎版本，不满足则该包不加载并报错）、`save_compat_min`（还能读的最旧存档版本）；`version` 即 pack 版本（点分数字）。引擎版本常量 `ContentCompat.ENGINE_VERSION`，`tools/checks/content_schema.py` 从同一文件取值校验 |
| 存档 | 新存档记 `content: [{id, version}]` 与 `engine`；读档由 `ContentCompat.check_save` 判定：缺包/版本更新/低于下限 = 拒绝并提示（不崩溃、不读入状态），旧但兼容/多启用了包 = 读入并提示；存读档页对该档位显示「内容包不兼容」。旧存档缺字段按原版包 |
| 样例 | `content/example_mod` 带整关 `stages/36`（地图+单位+`.evs`+对白）；`test_example_mod_stage_loads` 无头验证载入与编译 |
| 细则 | `docs/内容格式.md` §3、§3.1、§15 |

遗留：`tdj` 包版本升级后的**存档迁移**（数据表字段变更）仍只有存档格式迁移（`SaveFile.migrate`），没有按内容包版本的迁移钩子，目前靠 `save_compat_min` 拒绝过旧存档；包对引擎的要求只比较版本号，不检查指令集（`register_op`）是否齐全；示例关未自带贴图。

## 6. 锚点界面

为真宽屏「扩展视野」准备：画面基准比例是原版 16:10（320x200），但 16:9 很常见必须支持：设定「画面比例」缺省自适应——窗口/全屏比 16:10 宽时逻辑画面横向加宽
（16:9 → 356x200，21:9 → 约 467x200），比 16:10 窄（4:3）则上下留黑边；选「原版 16:10」始终留边（见 `docs/分辨率增强.md`）。
界面按「锚点」定位：16:10 下所有锚点偏移都是 0，画面与加宽前逐像素相同。

### 6.1 规则

- **逻辑画面** `size` = 视口可见大小 / `Assets.SCALE`；16:10 与「原版 16:10」模式恒为 320x200，自适应下宽屏随窗口加宽。
- **安全区** `safe_rect` = 原版 320x200 画面，在逻辑画面里居中（偏移取整到物理像素）。
- **原版坐标不变**。组件仍用对照原版 320x200 坐标，锚点只决定「安全区之外多出来的宽高」怎么分：
  锚点在左/上就不动，在中间各分一半，在右/下就整段平移。
- **锚点**：`TOP_LEFT` `TOP` `TOP_RIGHT` `LEFT` `CENTER` `RIGHT` `BOTTOM_LEFT` `BOTTOM` `BOTTOM_RIGHT` `STRETCH`。
  `CENTER` 即 `SAFE`（默认）；`STRETCH` 为全屏拉伸，只用于黑幕、淡入淡出这类纯色层。
- **成组的窗口整体用一个锚点**（如营地「囊内乾坤」两栏 + 说明栏），组内单独贴边的小件再嵌套锚点（如金钱框贴右上），
  嵌套时只平移两者之差。
- **全屏背景**（标题图、营地背景、店内背景、存读档页）按安全区居中，两边多出的部分用 `ScreenLayout.mirror_edges()` 镜像铺满并压暗（`engine/ui/edge_mirror.gd`）；视频不用，两侧留黑。
- 判断贴哪边按原版位置：离某条边 ≤ 约 1/4 画面、且与其他窗口不成组的贴那条边；居中摆放或成组的按安全区。

### 6.2 API（`game/engine/ui/screen_layout.gd`，autoload `ScreenLayout`）

| 接口 | 说明 |
|---|---|
| `size` / `safe_rect` | 逻辑画面大小、安全区矩形（原版像素） |
| `signal changed` | 视口大小变化（逻辑画面变了）时发出；下面各种绑定都会自动重新定位 |
| `offset(anchor)` / `px_offset(anchor)` | 该锚点下「原版坐标 → 画面坐标」的平移（原版像素 / 屏幕像素） |
| `to_screen(p, anchor)` / `to_original(p, anchor)` | 坐标换算（鼠标点击用后者） |
| `stretch_scale()` | 逻辑画面 / 320x200 |
| `anchor_node(anchor)` / `wrap(node, anchor)` | 锚点节点 `engine/ui/ui_anchor.gd`（放大 ×SCALE 的坐标系下用）：子节点照旧用原版坐标，UiSlide 等动画不受影响；可改 `anchor` 属性；子节点被删后自动删除 |
| `UiLayer.add(node, anchor := -1)` | 组件包进锚点节点；不传时取组件的 `ui_anchor` 属性，没有就 `SAFE` |
| `bind_layer(canvas_layer, anchor)` | 自带 CanvasLayer 的界面（Label 用 1280x800 像素坐标）：设 `layer.offset` |
| `bind_node(node, anchor)` | 挂在屏幕原点的场景根（Node2D/Control）：设 `position` |
| `cover(control)` | 让 ColorRect 铺满整个屏幕（不论挂在哪个坐标系下） |
| `mirror_edges(parent, z := 4000)` | 在 parent 末尾加边缘镜像层：把安全区里画好的画面镜像到宽屏两侧；z = 0 则只镜像在它之前加入的兄弟（如整页底图） |
| `set_aspect_mode("auto"/"keep")` / `widens(窗口, 模式)` | 画面比例模式（设定）；窗口 `MIN_WINDOW` = 1280x800 |

节点被绑定后带 meta `ui_anchor`，嵌套的锚点节点向上找最近的带 meta 的祖先（不越过 CanvasLayer）求相对偏移。
鼠标命中判断要用 `get_global_transform_with_canvas()`（含图层平移），不能用 `get_global_rect()`。

**调试开关**：`--aspect=16:9 | 4:3 | 21:9`（或任意 `W:H`）按比例设窗口（宽于 16:10 时高 800、加宽；窄于 16:10 时宽 1280、加高窗口），画面是否加宽由「画面比例」设定决定（`--aspect-mode=keep|auto` 临时指定）；不加参数时不改任何设置。

### 6.5 地图镜头加宽

战场：`battle_scene.gd` `view()` = 逻辑画面，根节点贴左上，`_clamp_cam` / `follow_cell` / 视差 / 剧情镜头（`_orig_to_view`、`orig_cam`）都按 view 算；
16:10 下 view = 320x200，与原版逐像素相同。触摸界面（`ScreenLayout.keep_side_margins`）左右留边给虚拟键，地图只占安全区宽度，留边铺纯黑 (原来画压暗的标题纹理, 2026-10-25 去掉)（`engine/ui/margin_backdrop.gd`）。

城镇 (`rpg_scene.gd` `view()` / `_clamp` / `_orig_to_view` / `orig_cam`，视口变化时 `_on_view_changed` 重新夹紧并回到主角) 与战场同一套做法。要点：

- 视口大小 `view = ScreenLayout.size`，场景根不按安全区平移，而是从屏幕左上角起画（`bind_node` 用 `TOP_LEFT`）。
- 镜头边界：`cam ∈ [0, map_size - view]`。地图某一维比 view 小时，这一维不滚动，地图居中：`cam = -(view - map_size) / 2`（负值），
  两边露出的部分画黑或装饰边。
- 镜头跟随目标（单位/主角）仍以 view 中心为准：`cam = 目标 - view/2`，再夹紧。原版「单位在第 n 行」之类的屏幕判断
  （信息条上下、行动菜单翻转、自动卷动的边距）改成相对 view 的比例或用 view 的行列数。
- 战场多图层视差的比例分母用 `msize - view`。
- 鼠标点格子：`(屏幕坐标 - 场景根位置) / SCALE + cam`（城镇已按此写）。
- 剧情脚本里的「镜头移到某格」(原版坐标) 先按 320x200 求出原版镜头位置，再加上 `(320x200 - view)/2` 让原版想看的区域仍在画面中间，最后夹紧。

## 7. 输入层与战场结构

### 7.1 统一输入层 `game/engine/input/`

| 文件 | 职责 |
|---|---|
| `ui_action.gd` `UiAction` | 动作：方向 ×4、确认、取消、查看、上/下翻页（原版逻辑键）+ 菜单、指向（鼠标悬停）、拖动、切换栏、空格按下/松开、长按松开；带 `echo`（按住连发）、`pos`（指针屏幕坐标）、`source` |
| `key_repeat.gd` `KeyRepeat` | 方向键按住 0.5 秒后每 0.1 秒连发（纯逻辑，有测试） |
| `touch_gestures.gd` `TouchGestures` | 点按 / 长按 / 拖动 / 左右快滑 / 双指点按 → 动作（纯逻辑，有测试） |
| `touch_pad.gd` | 手机虚拟键（只在手机或 `--touch`） |
| `input_router.gd`（autoload `InputRouter`） | 键盘、手柄、鼠标、触摸、自动测试事件 → 动作；界面栈 `push/pop`，`dispatch` 从栈顶往下传（接收方实现 `ui_action(a) -> bool`）；`held_dir()`（城镇行走电平）、`fast_held()`；F3/F4/F10 发信号给 Game; 键盘按键表见 `key_map.gd` (`KeyMap`, 可改键) |

接收方：标题、对话框、选择框、设定、视频、城镇（含物品界面）、商店、营地（`UiAction.camp_key()` 转成页面按键名）、战场（`BattleInput`）、升级窗、界面展示页。
键位与触摸映射见 3.1。

### 7.2 战场 `game/engine/battle/`
