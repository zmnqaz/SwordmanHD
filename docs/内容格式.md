# 内容包格式（tdj-content/1）

> 依据：`docs/架构设计.md` 第 0、4、5 节。
> 引擎运行时只读内容包，不读原版的原始文件。基础内容包 `game/content/tdj/` 由资源生成工具 从使用者自己的原版副本生成，不在本仓库。
> 运行时的读取接口见 §14，做改动包见 §15。本文说明「存在哪里、叫什么」。

## 1. 总则

- **一个内容包 = 一个目录** `game/content/<包名>/`，全部是 UTF-8 JSON（剧情脚本另定格式，见 §7）。
- **贴图、动画、音频不进内容包**，内容里只写**资源相对路径**，如 `Stage/Stage05/map05.png`、`Stage/Stage05/Eanm_01`（动画目录，内含 `anim.json`）。
  路径按顺序在各资源根下查找（`manifest.asset_roots`）：内容包自带的 `assets/`（改动包、原创包用）→ `hd4x/`（高清版，同路径）→ 原图仓库。
  原版内容包写的是原图仓库里的**真实大小写路径**（引擎仍按不区分大小写查找，兼容手写）。
- **以 `_` 开头的字段是注释**（显示名、来源、说明），引擎一律忽略。导入工具把可由编号查到的派生名（`type_name`、`item_names`…）写成 `_xxx`，方便人读。
  引擎显示名字时查 `data/enums.json` 或对应数据表，不读 `_` 字段。
- **编号**：单位模板、物品、技能等用整数 id（= 数组下标，从 0 起）；关卡、城镇用两位数字目录名；商店用字符串 id。
- **坐标**：格子坐标 (x, y) 从左上角 (0, 0) 起；像素坐标为原版 1 倍像素（320×200 画面），高清版由引擎乘 4。
- **原版怪癖照搬**：数据里的瑕疵（拿不到的宝物、XY 比 MAN 短等）原样保留，规则层按处理。导入时丢弃的东西记在 `manifest.import_warnings`。

## 2. 目录结构

内容分两个包：

| 包 | 内容 | 来源 | 发布 |
|---|---|---|---|
| `tdj` | 原版内容：数据表、关卡、城镇、营地、剧情脚本、系统文本、贴图分类表 | 全部由工具从原版游戏生成（资源生成工具），请勿手改 | `common_story.pck`（玩家自己生成） |
| `remake` | 复刻版自己的配置：`ui_theme/layout.json` 界面布局、`fonts.json` 字体清单、`assets.json` 资源命名、`fx/` 演出定位、`guide/` 游戏内攻略（§16） | 项目手写，入库 | 随程序（主 pck） |

`remake` 的 `base` 是 `["tdj"]`，是缺省主包（`content/content.json`），manifest 带 `"save_neutral": true`（只影响表现，不记入存档签名）。

```
game/content/tdj/
  manifest.json            包信息、基础包、资源根、数据表合并键
  data/
    units.json             单位模板 (Man_base.dat)
    items.json             物品 (Item_dat.dat)
    skills.json            绝技与咒术 (Mag_dat.DAT)
    levelup.json           我方升级成长与技能习得 (KMAN_LEV.DAT)
    party_init.json        我方初始状态 (KMAN_STA.DAT)
    attribute_defense.json 属性抗性表 (MAG_OPP.DAT)
    terrain.json           移动类型 × 地形类别的移动消耗 (TER_EFF.DAT)
    shops.json             商店 (各城镇 RPG_NN.DAT 的商店段)
    enums.json             各编号字段的显示名 (属性、物品类别、AI、地形类别、我方十人名…)
    misc.json              导入时保留的未知原始数据
  stages/NN/               战场关卡 (NN = 00..35, 原版 Stage/StageNN/)
    stage.json             关卡信息、资源、回合事件、地图事件、胜负条件、脚本与对白引用
    map.json               地图格 (地形类别、近景地面、地图事件号)
    layers.json            图层: 背景 (L0) 与物件 (L1)
    units.json             单位配置 + 出场坐标
    events_raw.json        剧情脚本的原始指令 (过渡期, 见 §7)
    text.json              对白表
  towns/NN/                城镇 (NN = 00..26, 原版 Rpg/RpgNN/)
    town.json  map.json  layers.json  events_raw.json  text.json
  scripts/                 剧情脚本 stage_NN.evs / town_NN.evs (docs/剧情脚本格式.md)
  camps/camps.json         各关之后的营地 (Camp/Script/CAMPNN.DAT)
  text/system.json         系统文本 (存读档确认、宝箱、得到物品、经验…)
  ui_theme/theme.json      界面主题占位 (空结构, 保留兼容; 实际布局/字体/资源命名在 remake 包的 layout/fonts/assets.json, 见 §11)
  textures.json            贴图分类表: 每张贴图的高清方式 (px = 运行时生成; 其余 = AI, 见 hd_images.pck)

game/content/remake/       手写配置 (见上表)
  manifest.json  ui_theme/{layout,fonts,assets}.json  fx/{cast,cutscenes}.json
  guide/                   游戏内攻略 (§16)
```

文件名固定，引擎按约定路径读取；`stage.json` / `town.json` 里对剧情脚本和对白写引用（**相对内容包根目录**的路径，改动包可指向别的文件）。
`scripts/` 目录（剧情脚本 `.evs`）随基础内容包生成，也可以直接手写 (格式见 [剧情脚本格式](剧情脚本格式.md))。

## 3. manifest.json

| 字段 | 含义 |
|---|---|
| `format` | 格式版本，现为 `"tdj-content/1"`。格式不兼容地改动时加一 |
| `id` | 包名（= 目录名），存档记录它 |
| `name` / `description` | 显示名、说明 |
| `version` | 包的版本（pack 版本，点分数字如 `1.3.0`，原版包 `1.3.0` = 官方 1.3）；存档记录它，读档时与当前版本比对 |
| `engine_min` / `engine_max` | 可选。本包要求的引擎版本范围（含）；引擎版本是 `game/engine/content/content_compat.gd` 的 `ENGINE_VERSION`（现 `1.0.0`），不在范围内时**该包不加载**并报 `Content:` 错误，不崩溃。引擎对包格式做不兼容改动时升它的主版本 |
| `save_compat_min` | 可选。本包还能读的最旧存档版本：存档里记录的该包版本低于它，读档被拒绝并提示 |
| `base` | 依赖的基础包 id 列表（按顺序先加载）。原版包为 `[]`；`remake` 写 `["tdj"]`；改动包只改数据时写 `["tdj"]`，改界面布局/演出时写 `["remake"]` |
| `save_neutral` | 可选，`true` 表示只影响表现（界面、字体、演出），不记入存档的内容包签名，读档也不比对 |
| `asset_roots` | 资源根的查找顺序（`assets` = 包内 `assets/`，`hd4x`，`original` = 原图仓库） |
| `stage_count` / `town_count` | 关卡数、城镇数（目录 `00`..`N-1`） |
| `ending_movies` | 播完后结束游戏、回标题的过场视频号（原版 `[13]`：第 31 关结局 Movie_13） |
| `start` | 可选。新游戏起点 `{"kind": "stage"\|"town", "id": 关卡号/城镇号, "entry": 城镇入口号 (仅 town, 缺省 0), "gold": 起始金钱 (缺省取规则参数 `initial_gold`), "movie": 开场过场号 (缺省不播)}`。缺省 = 第 0 关、`initial_gold`、无过场（原版行为）；`kind: town` 时出城去 `state.next_stage`（剧情 `set_stage` 设置，缺省第 0 关）。后加载的包整个替换。见 `templates/minimal_game/` |
| `tables` | 按键合并的数据表：`{表名: {"file": 包内路径, "key": 合并键字段}}` |
| `import_warnings` | 导入工具的警告（原版数据瑕疵，丢弃了什么） |

### 3.1 缺省主包与存档兼容（内容包版本策略）

- **缺省主包**不写在引擎代码里：由包目录根的 `content/content.json`（`{"main": "remake"}`）决定（`ContentDB.default_main()`）；没有该文件时取第一个没有 `base` 的包。命令行 `--content=<主包>` 可覆盖。
- **存档记录**：`"content": [{id, version}, ...]`（`Content.signature()`，主包与所有叠加包）与 `"engine": ENGINE_VERSION`。旧存档没有 `content` 字段时（内容包机制出现之前只有原版包）按 `tdj` 迁移补上（`ContentCompat.LEGACY_PACK_ID`，历史事实，不是配置）。
- **读档检查**（`GameSaves.check_content` → `ContentCompat.check_save`，存档位与战阵存录都查，不崩溃）：

  | 情形 | 结果 |
  |---|---|
  | 存档需要的包当前没加载 | 拒绝，提示缺哪个包与 `--mods=` 启用方法；存读档页该档位显示「内容包不兼容」 |
  | 存档里的包版本比当前新 | 拒绝，提示升级内容包 |
  | 存档里的包版本低于该包的 `save_compat_min` | 拒绝，提示过旧 |
  | 存档里的包版本比当前旧、但不低于 `save_compat_min` | 读入，读入后提示「已从 vX 升到 vY」 |
  | 当前多启用了存档创建时没有的包 | 读入，提示 |
  | 存档里的版本为空（旧档）或完全一致 | 通过 |

- 校验：`tools/checks/content_schema.py` 检查 `version/engine_min/engine_max/save_compat_min` 是点分数字、引擎版本落在要求范围内、`save_compat_min` 不高于 `version`；测试 `tests/test_content_compat.gd`。

## 4. Mod 覆盖规则

加载顺序：按 `base` 递归展开（基础包在前），再加当前包；玩家启用的多个改动包按设置里的顺序依次叠加
（命令行 `-- --mods=a,b` 或 `user://settings.json` 的 `"mods": ["a", "b"]`；主包默认 `tdj`，可用 `--content=<包>` 换）。
包目录在 `game/content/<id>/`（`res://content/`）或 `user://content/<id>/`，前者优先。后加载的覆盖先加载的：

1. **普通文件**（`stage.json`、`map.json`、`layers.json`、`units.json`、`text.json`、脚本、`theme.json`…）：**同路径整个文件替换**。
   例：改动包只放 `stages/05/units.json` 就只换第 5 关的单位配置，其他文件仍用原版的。
2. **数据表**（`manifest.tables` 列出的文件）：**按合并键逐条合并**：
   - 键相同：对象字段**深合并**（子对象递归合并，数组与标量整个替换），所以改一件武器的攻击只需写 `{"id": 0, "attack": 30}`；
   - 键不存在：追加为新记录（新物品 id 接在最后）；
   - 记录写 `"_delete": true`：删除该记录。
   改动包的数据表文件只写要改的记录。各包的 `tables` 声明合并后生效，后加载的包可以增加新表。
3. **新增关卡 / 城镇**：放新目录（如 `stages/36/`），并在自己的 manifest 里把 `stage_count` 改大（取各包最大值）。
4. **资源**：同一相对路径，后加载包的 `assets/` 优先。
5. **系统文本** `text/system.json`：按表名（第一层键）替换。
6. **语言叠加层** `locale/<lang>/<同路径>`（目前只有 `hant` 繁体；设计 `docs/设计_繁简切换.md`）：玩家在设定里选「繁體中文」（`Content.set_lang("hant")`）时，
   读一个文件先得到上面规则叠加后的结果，再把提供该文件的包及其后加载的包的 `locale/hant/<同路径>` 依次合上：**对象递归合并，数组与标量整个替换**；
   数据表按合并键只合并已有记录（叠加层只写不同的文字、不新增记录）；`text/system.json` 按表名替换；`text/ui.json` 按键合并。
   简体模式（缺省）不读 `locale/`，行为与没有这一层时逐字节相同。基础内容包 (tdj) 的 `locale/` 随内容包生成；手写文字（界面文案、枚举显示名）的繁体叠加层在 `game/content/remake/locale/hant/`，见 [设计_繁简切换](设计_繁简切换.md)。

## 5. 数据表（data/）

字段与原版数据表的字段**一一对应**（只把派生名改成 `_` 注释字段）。
字段的含义、取值和可信度；下表只列结构与要点。

| 文件 | 键 | 记录内容 | 原版来源 |
|---|---|---|---|
| `units.json` | `id` | 单位模板：`name`、`attribute_defence_id`（抗性表下标）、`move_type`、`camp`（0 我方/友军 1 敌方）、`hp`/`hp_grow`、`mp`/`mp_grow`、`move`、五项属性 `str int avg vit luk` 与各 `_grow`、`sprite`（动画编号）、`defence_type`、`attack_type`（0 近战 1 远程）、`base_lv`、`base_exp`；`unknown19` 未知 | `Misc/Man_base.dat`，58 字节/条 |
| `items.json` | `id` | 物品：`name`、`desc`、`type`（0 道具 1 武器 2 护具 3 饰物）、`equip_units`、`attack_range{type,area,min,max}`、`hit miss critical double`、`attack_add{type,ratio,time,turns,cost}`、`attack_attribute`、`attack`、`defence`、`attribute_defence{雷火冰幻光暗}`、`use{mp_cost,target,range_*,base_power,time_cost,consumable,use_type,effect,skill_id…}`、`price`、`synthesis`（炼化材料 [a,b] 或 null） | `Misc/Item_dat.dat`，182 字节/条 |
| `skills.json` | `id` | 技能：`name`、`desc`、`kind`、`can_use_after_move`、`target`、`range{…}`、`mp_cost`、`move_cost`、`power`、`rate6`/`rate10`、`attribute`、`result_type`、`result_effect`、`other_type`、`other_effect`、`spirit_addition[5]`、`animation_id`、`has_movie`、`battle_type`、`battle_ranged`、`battle_sprite` | `Misc/Mag_dat.DAT`，144 字节/条 |
| `levelup.json` | `unit_id` | 我方十人：`hp_rand`、`mp_rand`、五项属性 `{base, rand}`、`skills[{lv, spirit_request{五魂}, skill_id}]` | `Misc/KMAN_LEV.DAT` |
| `party_init.json` | `unit_id` | 我方初始：`lv exp hp mp`、五项属性、`spirit{五魂}`、`weapon armor accessory`、`in_team`、`spirit_points`、`items`、`skills` | `Misc/KMAN_STA.DAT` |
| `attribute_defense.json` | `index` | `values{雷火冰幻光暗}` 抗性百分比、`id_field` | `Misc/MAG_OPP.DAT` |
| `terrain.json` | `move_type` | `cost{地形类别 0..9: 移动消耗, null = 不可通过}`、`unknown10_14` | `Misc/TER_EFF.DAT` |
| `shops.json` | `id` | 见 §8.2 | `Rpg/RpgNN/RPG_NN.DAT` |
| `enums.json` | — | 显示名：`item_type attribute attribute6 spirit range_type target attack_add item_use item_effect skill_result skill_effect skill_other_type skill_other skill_add_type battle_type move_type camp ai kill_get shop_type attack_type terrain_class party`（键为编号字符串） | `生成工具的脚本` 常量；`shop_type` 取原版名称（商店物品窗左栏标签） |
| `misc.json` | — | `levelup_trailing_bytes_hex`：KMAN_LEV.DAT 末尾未解析字节 | — |

属性缩写：`str` 攻擊力、`int` 咒術攻擊力、`avg` 行動力、`vit` 防禦力、`luk` 機運；五魂键为 `迅 烈 神 魔 魂`（见 01 章）。

## 6. 关卡 stages/NN/

### 6.1 stage.json

```jsonc
{
  "id": 5,
  "name": "第五幕 十方鬼众",          // 关卡名 (Misc/STA_SCR.DAT), 存档摘要等处显示
  "music": 6,                          // 战场音乐编号 -> Music/Music_06 (STA_SCR.DAT)
  "briefing": {"title": "第五幕  十方鬼众", "win": "敌全灭", "lose": "殷剑平或封寒月死亡"},  // 任务简报 (SDES_NN.DAT)
  "assets": {
    "dir": "Stage/Stage05",            // 本关资源目录
    "title_card": "Stage/Stage05/TANM_05",    // 关卡标题卡动画 (指令 0x04)
    "battle_floor": "Stage/Stage05/Floor_05", // 近景战斗地面, 帧号 = map.json 的 floor
    "event_anims": {"1": "Stage/Stage05/Eanm_01", ...}  // 事件动画: 指令 0x18 的动画号 -> 动画目录
  },
  "turn_events": [{"turn": 1, "timing": 0, "event": 1}],
  "map_events": [{"index": 1, "type": 1, "trigger": 0, "event": 0, "item_type": 1, "item": 100, "prompt": 0, "show": 0}],
  "judge": {"win": [{"type": 1, "unit": -1, "event": 2}], "lose": [{"type": 2, "unit": 0, "event": 0}]},
  "script": {"source": "scripts/stage_05.evs", "raw": "stages/05/events_raw.json"},
  "text": "stages/05/text.json"
}
```

**turn_events**（`TEVT_NN.DAT`，6 字节/条 `turn timing event`）：按文件顺序，`timing` 匹配当前阶段且 `turn` 为当前回合或 −1 的**第一条**执行 `event` 号事件。
`timing`：0 我方阶段开始（友军行动前）、1 玩家操作前、2 敌方阶段开始（10 章 §1、§4）。

**map_events**（`MEVT_NN.DAT`，14 字节/条，下标 = 地图格的事件号）：

| 字段 | 原版字段 | 含义（12 章） |
|---|---|---|
| `index` | 下标 | map.json `event` 格引用它；0 号一般无效 |
| `type` | type | −1 无效，0 剧情事件，1 宝物 |
| `trigger` | parm1 | 触发者过滤：0 任何 / 1 友军 / 2 玩家 / 3 敌人（经过或停留）；4~7 同上但只算停留 |
| `event` | parm2 | 触发的事件号 |
| `item_type` | item_type | 宝物：0 事件宝物，1 物品，2 金钱 |
| `item` | item1 | 物品 id 或金额 |
| `prompt` | item2 | 开箱问句下标（数据全 0） |
| `show` | show | 宝箱图标排序键；−1 = 隐藏宝物（不画图标） |

**judge**（`JUDGE_NN.COD`）：先查 `win` 再查 `lose`，第一条成立的执行其 `event`。`type` 1 = 敌方全灭（`unit` 为排除的单位下标，−1 不排除），2 = 下标 `unit` 的单位离场。

**script** / **text**：见 §7。

### 6.2 map.json（`mapNN.dtl`，4 字节/格）

```jsonc
{"width": 27, "height": 37,
 "terrain": [[8, 8, ...], ...],   // 每行一个数组: 地形类别 0..9 (dtl 字节 0), 查 terrain.json 的移动消耗
 "floor":   [[0, 0, ...], ...],   // 近景战斗地面帧号 (字节 1), 不影响规则 (02 章)
 "event":   [[0, 0, ...], ...]}   // 地图事件号 (字节 2~3), 0 = 无, 否则为 map_events 下标
```

`terrain[y][x]`，行优先。原版判定只读事件号低字节（12 章 §1），数据里高字节都是 0。

### 6.3 layers.json（`LAYER_NN.DAT`）

```jsonc
{"backgrounds": [   // L0: 每个图层的底图 (文件头 c0-1 条, 60 字节/条)
   {"layer": 1, "z": 10000000, "view": [10, 8], "draw_layer": -1, "file": "Map05.mpl", "image": "Stage/Stage05/map05.png"}],
 "objects": [       // L1: 地图物件动画 (c1 条, 31 字节/条)
   {"layer": 1, "tag": 0, "x": 470, "y": 95, "flag_var": -1, "play_mode": 2, "delay": 0, "hidden": 1,
    "file": "Eanm_01.saf", "anim": "Stage/Stage05/Eanm_01"}]}
```

| 字段 | 原版 | 含义 |
|---|---|---|
| `layer` | id | 所属图层号。脚本切换图层（重制版 showLayer）时加载该号的底图与物件；不同图层在世界里纵向错开 |
| `z` | +2 (i32) | 深度值（原样保留） |
| `view` | u4,u5 | 尺寸参数：`[10, 8]`（一屏）为场景主图，其他（如 `[2, 2]`）为远景，叠在主图后面 |
| `draw_layer` | +20 | 原样保留，用途未定 |
| `file` | 名字 | 原版文件名（.mpl 地图 / .saf 动画），仅供追溯 |
| `image` / `anim` | — | 底图贴图路径；`.saf` 底图为动画目录 |
| `tag` | parm | 物件号：指令 0x25 显示 / 0x26 隐藏 / 0x28 播放一次 按它查找物件 |
| `x`, `y` | x,y | 像素位置（相对图层左上角） |
| `flag_var` | effect | 剧情变量号：≠ −1 时变量 > 0 才显示；指令 0x1E 按它成组显示/隐藏 |
| `play_mode` | pause | 0 循环播放，2 静止在第 0 帧，1 原样保留（2 处） |
| `delay` | +14 | 原样保留 |
| `hidden` | visible | 0 = 开场即显示，1 = 开场隐藏（由脚本显示） |
| `anim` | — | 动画目录路径（原图仓库没有该动画时为 null） |

### 6.4 units.json（`MAN_NN.DAT` 经 `data/stages.json`，+ `XY_NN.COD`）

数组，下标 = **单位下标**（脚本、胜负条件、AI 目标都按它引用；`index` 字段与下标相同，便于手改时对照）。

```jsonc
{"index": 2, "unit_id": 106, "x": 12, "y": 38, "_name": "封寒月",
 "lv": 0, "hp_add": 0, "hp_sub": 0, "mp_add": 0, "mp_sub": 0, "str": 0, "int": 0, "avg": 0, "vit": 0, "luk": 0,
 "spirit": {"迅": 0, ...}, "weapon": null, "armor": null, "accessory": null, "items": [], "skills": [],
 "event_parm": [0, 0], "kill_get_type": -1, "kill_get_parm": 0, "kill_event": 0, "unknown44": 0,
 "ai": -1, "ai_target": [0, 0], "unknown48_57": [0, ...]}
```

| 字段 | 含义 |
|---|---|
| `unit_id` | 单位模板 id（units.json） |
| `x`, `y` | 出场格子（XY_NN.COD 第 i 条给第 i 个单位）。**XY 比 MAN 短时后面的单位没有 x/y**（如第 12 关），由脚本放置 |
| `xy_unit_id` | 仅当 XY 记录里的单位 id 与 `unit_id` 不同时出现（原版没有此情况） |
| `lv` | 等级；`hp_add`/`hp_sub`/`mp_add`/`mp_sub`、五项属性：在模板上的增减 |
| `spirit`、`weapon`/`armor`/`accessory`、`items`、`skills` | 五魂、装备（null = 无）、物品、技能 |
| `event_parm` | [出场方式/阵营参数, …]，见 |
| `kill_get_type`/`kill_get_parm` | 击倒掉落：−1 无，0 金钱（parm = 金额），1 物品（parm = 物品 id）（12 章 §4） |
| `kill_event` | 被击倒时执行的事件号（−1/0 见 10 章） |
| `ai`、`ai_target` | AI 类型（enums.ai）与目标（单位下标或坐标）（09 章） |
| `unknown44`、`unknown48_57` | 未解析字段，原样保留 |

### 6.5 text.json（对白，`EMSG_NN.MSG` 经 `data/emsg/`）

`{"_source": "Stage/Stage05/EMSG_05.MSG", "groups": [[句子, ...], ...]}`：组号 = 事件号，句号 = 对白指令里的句子号。
`\n` 为换行，`{0}` 为数字/名称占位符。文本为简体。

## 7. 剧情脚本（引用位置）

`stage.json` / `town.json` 的 `script`：

| 字段 | 含义 |
|---|---|
| `source` | 可读脚本 `scripts/stage_NN.evs` / `scripts/town_NN.evs`（命令名 + 参数，随内容包生成，格式见 `docs/剧情脚本格式.md`） |
| `raw` | `stages/NN/events_raw.json`：原版 `EVENT_NN.COD` 的指令原样转存，`[[{"op": 指令号, "data": "参数字节 hex"}, ...], ...]`，下标 = 事件号 |

引擎执行 `source`：载入关卡/城镇时由 `game/engine/script/evs_compiler.gd` 编译成与原版字节码逐条相同的指令序列
（指令表 `game/engine/script/evs_ops.json` 由 `tools/assets/compile_events.py --export-ops` 从 Python 指令表导出），
再交给战场 `EventVM` / 城镇 `RpgVM` 执行，所以行为与执行原版 COD 一致（`tests/test_content.gd` 对照 63 个脚本）。
`raw` 只在 `source` 文件不存在时作为保底，以及作为校验依据；改动包改剧情只需放同路径的 `.evs`。
战场与城镇脚本都按「事件号」组织，`turn_events`、`map_events`、`judge`、`kill_event`、城镇格子的 `talk`/`step` 都引用事件号。

## 8. 城镇 towns/NN/

### 8.1 town.json

```jsonc
{"id": 5,
 "assets": {"dir": "Rpg/rpg05", "map_file": "map05.mpl", "map_image": "Rpg/rpg05/map05.png"},
 "entries": [{"music": 61, "map_x": 0, "map_y": 4, "x": 5, "y": 8, "dir": 3}, ...],
 "shops": ["town05.0", "town05.1", "town05.2"],
 "script": {"source": "scripts/town_05.evs", "raw": "towns/05/events_raw.json"},
 "text": "towns/05/text.json"}
```

- `assets.map_image`：城镇地图贴图。部分城镇共用别处的地图（如 1、3 用 Rpg00 的 map00，重制版 MAP_FIX），导入时已解析成最终路径。
- `entries`（`RPG_NN.DAT` 前 2×12 字节）：入口，下标 = 入口号（营地、脚本跳转时指定）。`music` 音乐号、`map_x/map_y` 镜头起点（格）、`x/y` 主角格子、`dir` 朝向（动画方向序号 0 南 1 西 2 北 3 东，见原图仓库 README）。
- `shops`：本城商店 id，下标 = 商店指令的商店号。
- `map.json`（`mapNN.dtl`，无则取目录里第一个 .dtl，来源记在 `_source`）：`block`（0 = 可走）、`talk`（对话事件号，调查/对话该格时执行）、`step`（踩踏事件号）。
- `layers.json`：只有 `objects`（NPC 与场景动画），字段同 §6.3；`file` 带扩展名，引擎按去掉扩展名的目录名找动画。
  开场播放条件：`layer` = 1、`play_mode` = 0、`flag_var` = −1；其余由脚本（添加/播放动画指令按 `layer` + `tag` 查找）控制。

### 8.2 data/shops.json

`{"id": "town05.0", "type": 0, "keeper": 6, "items": [0, 15, 45, 95], "keeper_anim": "Shop/Shop06", "_item_names": [...]}`

`type` 商店类别（按原版数据观察：0 武器护具、1 饰物、2 道具）；`keeper` 店主动画号（`Shop/ShopNN`，第 0 帧为店内背景）；`items` 出售物品 id（原版每店最多 24 格，−1 空格已去掉）。
改动包可按 id 改货单，或新增商店并在城镇的 `shops` 里引用。
`show`：进出店的场景演出（通用 SceneShow 配置，`game/engine/ui/scene_show.gd`），导入时按原版 规则生成：
`{"anim": "Shop/Shop06", "base": 0, "intro": [1, 40], "loop": [42, 40], "fade_in": [2,4,...,14], "fade_out": [14,...,2], "fade_tick": 2}`
—— `base` 底图帧；`intro` 开场段 [起始帧, 帧数]（播完才打开物品窗）；`loop` 待机段（帧数 −1 = 到最后一帧）；
`fade_in`/`fade_out` 渐入/渐出各档不透明度 x/16，每档 `fade_tick` 个 40 ms 时钟。缺 `show` 时引擎按 `keeper_anim` 用同一规则生成。

## 9. 营地 camps/camps.json（`Camp/Script/CAMPNN.DAT`，6 字节）

数组，键 `stage`：第 `stage` 关结束后进入的营地。

`{"stage": 3, "background": 3, "town": 2, "town_entry": 1, "background_anim": "Camp/Image/camp03"}`

- `background`：背景动画号（`Camp/Image/campNN`；原版没有该动画时 `background_anim` 为 null，营地无背景，如第 34 关）。
- `background_show`：背景的场景演出配置（同 §8.2 `show`，营地为 `{"anim": ..., "loop": [0, -1]}` 整段循环），无背景时为 null。
- `town` / `town_entry`：离开营地时去的城镇与入口；`town` = −1 则直接进入下一关。
- 原版缺 `CAMP32.DAT`，按现有运行时的缺省值 `(0, -1, 0)` 填写并加 `_note`。

### 10.1 界面文案 text/ui.json

扁平 `{键: 文字}`，引擎里的界面文案（设定面板、营地主菜单、标题菜单）经 `UiStrings.t(key[, args])`（`game/engine/ui/ui_strings.gd`）取，不写死在脚本里。项目自带的缺省文案在 `content/remake/text/ui.json`（`content/tdj/` 是生成包不能手改）。
- 叠加：按包加载顺序逐键合并，后加载的包覆盖前面；值写 `null` 删除该键；`_` 开头的键视为说明不入表。mod 只写要改的键即可。
- 键名：`<界面>.<元素>[.<子项>]`，如 `settings.music.label`（行名）、`settings.music.desc`（行说明）、`settings.gfx.opt.hd`（选项文字）、`settings.title`、`camp.menu.item.0`、`title.menu.item.2`。缺键时界面显示键名并警告一次。
- 带参数的文案写 `%s`/`%d`，`UiStrings.t(key, [args])` 按 `%` 格式化。
- 「文案归内容包」的最小通道，不是 `tr()` 式国际化；语言（简体/繁体）靠内容包的 `locale/hant/text/ui.json` 叠加层切换（§4 第 6 条）。尚未迁移的硬编码文案以代码里的中文字面量为准。
- 验证：`tests/test_ui_strings.gd`（文案逐字一致、覆盖/删除规则）。

## 14. 运行时接口（`game/engine/content/content_db.gd`，autoload `Content`）

运行时一切游戏内容都经 `Content` 取，引擎代码不直接读 `data/`、原图仓库里的 COD/DAT，也不写关卡号特判。

| 接口 | 说明 |
|---|---|
| `load_packs(ids)` | 按顺序加载包（各包先递归加载 `base`），返回是否无错；错误在 `errors`。测试/工具可 `ContentDB.new()` 另建一份 |
| `packs` / `pack_dirs()` / `signature()` | 已加载的包（加载顺序）、各包目录、`[{id, version}]`（写进存档 `content` 字段） |
| `find(rel)` / `json(rel)` | 后加载优先的同路径文件（整个替换）/ 其 JSON |
| `table(name)` / `table_array(name)` / `record(name, key)` | `manifest.tables` 的合并结果：按加载顺序的记录数组 / 下标 = 整数键的数组（空位为 `{}`）/ 单条 |
| `unit(id)` `item(id)` `skill(id)` `units()` `items()` `skills()` | 单位模板、物品、技能 |
| `levelup(uid)` `party_init(uid)` `is_hero(uid)` | 成长表、初始状态；`is_hero` = party_init 表里有该单位 |
| `attribute_defense(i)` `terrain(move_type)` `shop(id)` `camp(stage)` `enums(name)` | 抗性、地形消耗、商店、营地（无记录时按原版缺省：无背景、直接下一关）、显示名 |
| `stage_count()` `stage_info(n)` `stage_file(n, f)` `stage_name(n)` | 关卡（结构类数值转成 int） |
| `town_count()` `town_info(n)` `town_file(n, f)` | 城镇 |
| `events(script)` | `stage.json`/`town.json` 的 `script` → 编译后的指令 `[[{type, data}]]`（缓存） |
| `text_groups(rel)` `system_text(name)` `theme()` | 对白表、系统文本（按表名替换）、界面主题 |
| `is_ending_movie(id)` | `manifest.ending_movies` |
| `params()` | 规则参数：原版默认值上依次叠加各包根目录的 `rules.json`（`game/engine/rules/README.md`），战斗规则上下文用它 |
| `asset_file(rel)` | 包内 `assets/` 的覆盖文件（不区分大小写，后加载优先）；`Assets.path/tex/anim/sound/music/exists` 先查它，再走原有的 hd6x/hd4x/原图仓库查找 |

仍在引擎里的原版约定（不能数据化）：资源命名规则 `Music/Music_NN`、`Movie/Movie_NN`、`Sprite/manNNN/NNNman`、`Face/`、
`Misc/` 界面素材；召唤标志变量 103~106（规则模块 `battle_rules.gd`，属规则参数）；`--camp-gsf` 调试开关读原版存档 GSF（导入对照用，不是内容）。

## 15. 如何做 mod（改动包）

示例：`game/content/example_mod/`（殷剑平移动力 23→26、长剑售价 45→30、回合上限 100→120；另带**完整的一关** `stages/36/`：地图 + 单位 + 剧情 `scripts/stage_36.evs` + 对白，`manifest` 写 `"stage_count": 37`），
`tests/test_content.gd` 验证覆盖生效、`test_example_mod_stage_loads` 验证该关用 `--mods=example_mod` 的路径能载入并编译；
示例关的地图是简单的竞技场，底图贴图只引用基础包素材；要自带贴图放包内 `assets/`（第 5 步）。单位默认不在场，剧情里要 `show ids=...` 才出现。

1. **建目录** `game/content/<包名>/`（或玩家目录 `user://content/<包名>/`），写 `manifest.json`：
   ```json
   {"format": "tdj-content/1", "id": "example_mod", "name": "改动包示例", "version": "0.1.0", "engine_min": "1.0.0", "base": ["remake"], "tables": {}}
   ```
   `id` 必须等于目录名；`version` 是点分数字（存档会记录，见 §3.1）；`engine_min` 写你开发时的引擎版本；`base` 写依赖的包（基础包 `tdj`）。`tables` 可省略或为空：沿用基础包声明的数据表；要加新表才在这里声明。
2. **改数据表**：在同路径放只含要改记录的文件，按键深合并（§4）。
   ```json
   // data/units.json            // data/items.json
   [{"id": 0, "move": 26}]       [{"id": 0, "price": 30}]
   ```
   新增记录写新键（物品 id 接在最后）；`{"id": 5, "_delete": true}` 删除；子对象可只写要改的字段（如 `{"id": 0, "attack_range": {"max": 3}}`）。
3. **改规则参数**：包根目录放 `rules.json`：`{"format": "tdj-rules/1", "params": {"turn_limit": 120}}`，参数名见 `game/engine/rules/params.gd`。
4. **改关卡 / 城镇 / 剧情 / 对白**：放同路径文件整个替换，如 `stages/05/units.json`、`scripts/stage_05.evs`（格式见 `docs/剧情脚本格式.md`，
   可先用 `python3 tools/assets/compile_events.py X.evs /tmp/x.COD` 检查语法）、`stages/05/text.json`。新关卡放 `stages/36/` 并在 manifest 写 `"stage_count": 37`。
5. **换图换音**：放到包内 `assets/` 下与原版相同的相对路径（如 `assets/Stage/Stage01/map01.png`，原版 1 倍大小；动画目录连同 `anim.json` 一起放）。
6. **启用**：`tools/run_game.sh -- --mods=example_mod`（多个用逗号，按顺序叠加），或在 `user://settings.json` 写 `"mods": ["example_mod"]`。
   启动日志第一行 `Content: tdj 1.3.0, example_mod 0.1.0` 列出实际加载的包；加载错误（找不到包、格式不对、脚本编译错误）打印为 `Content:` 开头的错误。
7. **验证**：`tools/godot/godot --headless --path game --script res://tests/run_tests.gd -- test_content`；改了数据表的话可仿照 `test_example_mod` 加断言。

> 写完后用 `python3 tools/checks/content_schema.py --pack <目录> --strict` 校验（未知字段、rules 参数、资源路径、保留变量）；完整教程见 `docs/新游戏接入指南.md`。

## 16. 游戏内攻略 guide/（可选）

F4 / 设定面板「攻略」打开的攻略面板（`game/engine/ui/guide_panel.gd`，操作见 4.5）读这里。**可以没有**：
内容包里没有 `guide/guide.json` 时设定面板不列「攻略」，热键打开的面板只显示「没有攻略」。mod / 新游戏要带攻略就放同样的文件（后加载的包同路径整个替换）。

```jsonc
// guide/guide.json  目录: 章的顺序 = 面板左栏顺序
{"format": "tdj-guide/1",
 "chapters": [
  {"id": "ending", "file": "guide/ending.json"},               // 非关卡章 (完美结局、技能与练级...)
  {"id": "stage_05", "file": "guide/stage_05.json", "stage": 5} // 关卡章: stage = 关号 (stages/NN)
 ]}
// guide/stage_05.json  一章
{"title": "第5幕 十方鬼众",   // 正文上方的标题
 "label": "5 十方鬼众",        // 左栏的短名 (超出栏宽按字节截断)
 "stage": 5,                   // 说明用, 引擎按目录里的 stage
 "body": "**胜利条件**\n\n- 击倒..."}
```

- `body` 是 markdown 子集，面板运行时转成 RichTextLabel 的 BBCode（`game/engine/ui/guide_text.gd`）：标题 `#`~`######`（一律显示成小标题）、列表 `- ` / `* `（行首每两格空格缩进一级）、粗体 `**x**`、分隔线 `---`、空行；其余原样显示（`[` `]` 会被转义）。**表格不支持**，请写成列表。
- 默认打开哪一章：战场里 = 本关，城镇/营地 = 下一关（`state.next_stage`）；该关没有章时取关号不超过它的最近一章（`GuideBook.index_for_stage`）。
- 繁体：叠加层 `locale/hant/guide/<同名>.json`（对象深合并，只写不同的字段，规则同 §4 第 6 条）。目录 `guide.json` 不需要叠加层。
- 营地「五魂化蘊」按查看键/空格直接打开当前这个人的 `spirit_<单位号>` 页（`GuidePanel.open_chapter`，内容包没有这章就按默认章）。
