# 保留变量表

<!-- 由 tools/docgen/reserved_vars.py --write-doc 生成, 请勿手改 (改 tools/docgen/reserved_vars.py 的 FIXED 后重新生成) -->

剧情变量 (`.evs` 的 `set_var/add_var/sub_var/if_var ...` 的 `var`) 是一个字典, 键 0~127 供脚本使用 (原版 128 个 int32, 新游戏全部清 0, 关卡切换与读档都不清)。
`>= 128` 的键被引擎占用 (如 `1000 + 角色号` = 离队标志), 脚本不得使用。`python3 tools/checks/content_schema.py --strict` 会对越界和下面标 **engine** 的变量的写操作报错。

| 变量 | 级别 | 含义 | 依据 |
|---|---|---|---|
| 1 ~ 17 | tdj | 原版剧情: 关内开关 var1~7、关内计数 var8~10、跨关分支 var11~17 (夏侯仪入队 14、修剑路线 16 ...) | 原版剧情数据 |
| 30 ~ 65 | engine | 第 `var-30` 关的过关回合数 (stage_over 写 `30 + next`; 通关序号 `show_clear_rank` 读 30~64); 新游戏关数更多时占 `30 .. 30+关数`; 基址/区间/异或常量是 rules.json 参数 `turn_record_base` / `clear_rank_segments` / `clear_rank_xor` (默认 = 原版, -1 = 不记) | rules/clear_rank.gd; event_vm.gd _stage_over |
| 80 ~ 90 | tdj | 原版城镇剧情: 醉汉/酒 80~82、杂货店 81、绿衣人 85、京城挖宝 88 ... | 原版城镇剧情数据 |
| 100 | engine | 最近一次行动者的单位下标 (普攻/法术/道具都写) | battle_actions.gd |
| 101 | engine | 普攻的被攻击者下标; 法术/道具写 -1 | battle_actions.gd |
| 102 | engine | 当前行动单位下标 (玩家选中 / AI 开始行动时写; 地图事件里 = 踩格者, kill_event 里 = 击杀者) | battle_flow.gd / battle_input.gd 读 params.var_actor (rules.json 可改, 默认 102) |
| 103 ~ 106 | engine | 召唤标志 (每关开始清 0; 召唤成功置 1, 召唤物死亡清 0) | params.summon_flag_vars (rules.json 可改, 默认 [103,104,105,106]) |
| (技能表给定) | summon | 召唤技能的标志变量 = 该技能记录的 `rate10` (技能表里 result_type 5 / result_effect 14); 校验时按内容包的技能表扫描 | skills.gd summon_flag_var |

级别: **engine** = 引擎自己会写, 脚本只应读; **tdj** = 原版剧情脚本占用, 基于 tdj 的改动包写它们会改变原版分支 (校验只提示, 不报错); 新游戏 (`base: []`) 可以自由使用 tdj 级变量。

表里没有的变量号 (0、18~29、关数更多时 30+关数 之后的 67~79、91~99、107~127 等) 都是空闲的, 变量 0 没有特殊含义。关卡之间不清变量: 关内局部变量请在事件 1 开头用 `set_var` 重新赋值。
